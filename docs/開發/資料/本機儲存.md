# 本機儲存

這份文件說明檔案放在哪、怎麼保護，以及完整備份帶不帶。演算法細節見[加密格式](../安全/加密格式.md)，備份與還原流程見[備份與還原](../功能/備份與還原.md)。

App 資料根目錄為 `{applicationSupport}/quill_diary/`，由 [`VaultPathStrategy`](../../../lib/infrastructure/storage/vault_path_strategy.dart) 計算；下文以 `{appSupport}` 表示同一系統目錄。Android 原生 Drive 暫存另在 `filesDir`，不要把兩個根目錄混用。

`android:allowBackup="false"` 關閉雲端 Auto Backup，但 Android 12+ 部分廠牌仍允許裝置移轉；未被主 Manifest 引用的備份 XML 不生效，也不能以舊 release 合併產物判定目前設定。詳見[Android 系統備份限制](../google/Android-權限與資料揭露.md#套件查詢與系統備份)。

## `{appSupport}/quill_diary/vault/`

| 路徑 | 內容 | 保護 | 完整備份 |
|------|------|------|----------|
| `recovery.json` | 復原 metadata 與 KDF 描述，不是可直接解檔的密鑰 | 明文 | 包含 |
| `manifest.json.enc` | 日記庫 manifest | LDJ2 | 包含 |
| `people.json.enc` | 人物名冊 | LDJ2 | 檔案存在時包含 |
| `ai_settings.json.enc` | 具名連線集合、目前預設連線 ID、模型與 Thinking JSON 對照、網址、協定、Workspace ID、聊天日記與日記整理的自訂提示詞，以及 AI 功能開關與人物隱藏。沒有 API Key 欄位。尚未存過設定時不建立 | LDJ2，與日記同一把復原包裝金鑰 | 檔案存在時包含 |
| `entries/` | 正式日記 `*.md.enc`，以及相鄰的完成聊天 `*.chat.json.enc` | LDJ2 | 包含 |
| `assets/` | 正式附件 | LDJ2 | 包含 |
| `tag_styles.json` | 標籤目錄與樣式 | 明文 | 已保存時包含 |
| `pinned_entries.json` | 釘選日記 ID | 明文 | 已保存時包含 |
| `chat_diary_drafts/` | 未完成聊天、原圖，以及該聊天的生成草稿 | LDJ2 | 排除 |
| `diary_organization_drafts/{entryId}/session.json.enc` | 日記整理的來源、隱藏標記、聊天分支、單一目前稿、輸入與套用狀態 | LDJ2 | 排除 |
| `chat_diary_remote_cleanup/` | 服務商暫存檔的清理紀錄，不含 API Key | LDJ2 | 排除 |
| `personas/<person_id>/state.json.enc` | 分身正式內容及未完成草稿 | LDJ2 | 僅正式內容，備份時排除草稿並重新加密 |
| `personas/<person_id>/pending_imports/` | 建立分身使用的匯入聊天原文 | LDJ2 | 排除 |
| `quarantine/` | 修復時隔離的損壞或衝突內容 | 沿用原檔 | 排除 |

| `recovery_rotation.pending` | 未完成復原金鑰輪替的恢復材料，內含新金鑰與前後 metadata | 以舊包裝金鑰保護的 LDJ2 | 若殘留，目前打包過濾器未排除 |

`tag_styles.json` 與 `pinned_entries.json` 讀取失敗時保留原檔並當成空資料，不以舊副本覆蓋；只有明確寫入空內容才刪除檔案。

LDJ2 檔頭包含可讀的檔案 ID、日記庫 ID、內容類型與時間，並作為正文的附加驗證資料；正文才加密。明文 metadata、檔名與路徑仍會揭露部分結構，不能把整個資料目錄或 ZIP 外層稱為加密。

### 各操作的掃描範圍

| 操作 | 範圍與邊界 |
|------|------|
| 金鑰維護 | 恢復並驗證中斷替換後，處理日記庫內加密檔；包含 AI 設定、聊天與整理草稿、分身及遠端清理紀錄，不等於完整備份範圍 |
| 分身還原 | 只接受 `personas/<person_id>/state.json.enc`；拒絕匯入材料、額外草稿檔、替換副本與非標準分身路徑 |
| 日記庫修復 | 掃描 `entries/`、`assets/`，不把 AI 設定當日記；完成聊天不可讀或沒有對應日記時，只隔離聊天檔 |
| 日記位置修復 | 日記離開 `entries/` 時刪對應整理草稿；只搬回正確日期時保留。未完成聊天草稿不在此掃描範圍 |

## AI 格式與版本規則

版本集中於 [`DataVersions`](../../../lib/shared/data_versions.dart)，各格式獨立管理，不設 AI 總版本或提示詞版本。

| 格式 | 版本 | 編解碼入口 |
|------|------|------|
| AI 設定 | 2 | `AiStoredSettings` |
| 聊天日記 | 1 | `ChatDiarySession` |
| 日記整理 | 1 | `DiaryOrganization` |
| 人物分身 | 1 | `PersonaRecord` |
| 分身匯入內容 | 1 | `PersonaChatImport` |

只有既有資料無法正確解讀的結構、型別或語意變更才升版。提示詞、UI、模型目錄、預設值及有明確預設值的可選欄位新增都不升版。尚未發行的功能以首次正式格式為第 1 版，不保留開發過程的搬移。App 版本、金鑰版本、執行工作序號與內容雜湊維持各自用途。

### 設定與連線快照

`AiStoredSettings` 負責純 JSON 編解碼；`AiSettingsStore` 負責加解密、模型目錄更新、檔案操作與裝置 API Key。設定只讀寫目前第 2 版，儲存欄位如下：

| 欄位 | 內容與缺省規則 |
|------|------|
| `version`、`connection` | 必要版本與連線設定；連線使用 `active_connection_id`、`connections` |
| `ai_enabled` | 可選布林；「啟用 AI 功能」開關，缺省 true |
| `hide_people` | 可選布林；共用的人物隱藏開關，缺省 true |
| `chat_diary` | 可選物件，缺省空物件；各覆寫為可選字串，缺省 null：`personality_prompt_override`、`guidance_prompt_override`、`generation_prompt_override` |
| `diary_organization` | 可選物件，缺省空物件；對話與生成覆寫為可選字串，缺省 null：`conversation_prompt_override`、`generation_prompt_override` |

空白覆寫不保存；有內容的原文保留。官方連線使用固定 ID，自訂連線使用 ULID。API Key 依穩定連線 ID 與正規化目的地存於裝置，不隨備份搬移。

連線設定使用 `fromStoredJson`／`toStoredJson`，保存模型清單與已看過的官方目錄；請求快照使用 `fromSnapshotJson`／`toSnapshotJson`，只保存當時目的地、模型與該模型的 Thinking 設定。編解碼不更新目錄；設定儲存入口明確套用目錄更新，只有內容變動才回寫。既有請求快照不依目前目錄重新解讀。

### 提交與恢復

AI JSON 驗證日記庫、檔案身分、內容類型及資料結構。排隊前取得完整序列化快照，替換前讀回驗證暫存檔。成功提交後的清理失敗不回報為提交失敗，殘留檔於下次操作清理。

設定、聊天與整理在主檔存在時只驗證主檔，不以舊副本取代損毀主檔。主檔不存在時，先選 `.previous`，沒有才選 `.tmp`。候選通過驗證後才恢復；驗證失敗則保留現場。人物分身不自動恢復可能過期的副本。

不搬移安全儲存中的舊 `settings`／`chat_diary_settings`。也不接受舊欄位別名，或推測重建人物資料。聊天姓名區間只使用已存的 `person_ranges`，缺少時為空。日記整理保留目前 P／S 代號與別名還原對照，不轉換歷史長代號；詳細欄位與套用中斷恢復見下方的[日記整理 JSON](#日記整理-json)。

無 AI 設定檔時使用預設值。設定讀取失敗可明確重設，在明確確認後一次寫入第 2 版預設設定並整理替換副本；其他不相容 AI 資料由對應功能刪除重建。未知未來版本拒讀，不自動覆寫。這些操作不清除正式日記、圖片、附件、裝置 API Key 或遠端清理紀錄。

### 人物分身提交與備份

[`PersonaStore`](../../../lib/infrastructure/persona/persona_store.dart) 管理人物目錄 `personas/<person_id>/`。`person_id` 使用 `per` 前綴，分身生命週期 `persona_id` 使用 `prs` 前綴；刪除重建會換分身 ID，舊聊天不會自動接回。

- `state.json.enc`：正式卡片 `memory`、`tone` 各保存文字、人物對照、更新時間與選取日記 ID；可另有一份 `draft`，保存更新目標、步驟、基準、模型、材料參照、隱藏區間與候選內容。
- `pending_imports/<import_id>.<content_id>.json.enc`：不可變的匯入聊天。`import_id`（`pim`）在編輯間維持不變，每次寫入產生新的 `content_id`（`pco`），兩者皆使用帶前綴的 ULID。加密身分同時綁定人物、匯入與內容 ID。

草稿保存使用獨立於生成工作的記憶體生命週期與修改序號，每次排入日記庫修改序列前同步擷取快照。鎖定及控制器釋放不取消已擷取的本機修改；生成結果仍另檢查工作有效性。新建草稿、捨棄更新及刪除會使舊生命週期的保存失效。收尾寫入不允許建立不存在的分身，仍驗證日記庫、人物、分身識別與卡片基準；成功回呼僅清除同一修改版本的待存狀態。

匯入與移除聊天材料前，先保存既有本機修改，再提交新的材料指標，避免鎖定收尾還原已被清理的舊指標。

匯入修改的提交順序固定如下：

1. 寫入新內容檔並讀回驗證。
2. 一次提交包含新內容指標、隱藏／排除設定與候選狀態的分身檔。
3. 清除不再引用的內容檔，回傳成功後才更新控制器的記憶體。

狀態提交失敗時，舊指標與舊內容仍有效；新孤立檔下次載入清理。清理失敗只更新待清理旗標。

完整備份在同一次日記庫修改序列內，取得已正式儲存的卡片與識別，將 `draft` 設為 null 後重新加密為 LDJ2，寫入備份中的相同狀態路徑。原始分身目錄不直接打包，只有草稿或正在刪除的分身不納入；備份也不修改使用中的狀態與匯入檔。

本機與 Drive 共用這條備份流程。還原只接受標準分身狀態路徑，拒絕匯入材料、額外草稿檔或替換副本；還原得到備份當下的正式內容，不恢復未完成進度。金鑰輪替則仍涵蓋所有分身加密檔。

### 設定檢查與重建

目前 AI 設定寫入第 2 版；第 1 版設定不相容，依下方規則重設。人物分身仍為第 1 版，不受影響。

`inspect()` 在修改序列內唯讀檢查主檔、`.previous`、`.tmp`，回傳狀態與內容指紋，不搬移、不採用目錄、不寫檔。一般 `read()` 則允許經驗證的替換恢復及目錄更新。只有 `replaceUnreadableWithDefaults()` 可在使用者確認後略過舊格式驗證，重新比對指紋並一次提交預設設定；期間資料已改變則停止。替換失敗保留選定的原內容；替換過程會整理替換副本，不提供設定歷史。

重建不刪裝置 API Key。官方提供商可沿用 Key；自訂連線的新 ID 不同，需重新輸入 Key，不以相同網址跨連線取用。設定內容錯誤、磁碟錯誤、鎖定各自處理；不自動外送失敗前的請求。

### 連線 JSON

| 欄位 | 設定／快照規則 |
|------|------|
| `provider`、`default_model` | 必要；供應商 enum 名稱與模型 ID |
| `connection_id` | 自訂連線的穩定 ID；缺少時沿用既有 `custom` 金鑰識別，不改名 |
| `display_name`、`base_url`、`workspace_id` | 可選字串，缺省空字串；網址只用於 Custom |
| `protocol` | 可選，缺省 `chatCompletions`；官方服務依提供商決定協定 |
| `added_models`、`enabled_models`、`known_builtin_models` | 設定格式必要清單；快照不帶這些目錄欄位 |
| `thinking_levels` | 可選模型→強度對照，缺省空物件；提供後每項須合法，不略過壞值 |
| `thinking_overrides` | 可選模型→覆寫，缺省空物件；每個覆寫的 `levels` 必要，`default_level` 必須符合啟用檔位；空 `levels` 與 null 預設代表不傳參數 |

明確建立工作或套用連線時固定當時設定；請求快照的 `thinking_levels`、`thinking_overrides` 只序列化選定模型的對照，不帶整份模型目錄。各次外送使用工作快照，重試建立新回覆但不改舊快照。歷史缺少的實際預設不推測回填；不完整的舊工作須重新選擇模型才可外送。快照參數供歷史請求使用，不當成目前全域設定。

### 聊天日記 JSON

| 欄位 | 必要／可選與缺省 |
|------|------|
| `schema_version`、`id`、`vault_id`、`config` | 必要，版本為整數 1；識別須與所在日記庫及檔案相符 |
| `hide_people`、`created_at`、`date` | 必要；人物隱藏、建立時間及日曆日期 |
| `messages`、`images`、`replacements`、`token_keys` | 必要清單／對照；`token_keys` 的每個值必須存在於 `replacements` |
| `composer_text`、`composer_ranges`、`pending_image_ids` | 可選，缺省空字串、空清單、空清單 |
| `diary_prompt`、`opening_message` | 可選，缺省空字串 |
| `finished` | 可選，缺省 false |
| `selected_children` | 必要物件；分支不得懸空或形成循環 |
| `generation_connection`、`generated_entry_id`、`generated_from_message_id`、`generated_draft_signature` | 可選，缺省 null |
| `editing_message_id`、`edit_backup` | 可選，缺省 null；有編輯目標時需有效目標及備份 |
| `selected_persona`、`persona_participants` | 可選，缺省 null、空物件；只保存分身識別及顯示資料 |

訊息必要欄位為 `id`、`is_user`、`text`、`outbound_text`。可選的 `image_ids`、`private_ranges`、`person_ranges`、`private_token_ids` 缺省空清單；`status` 缺省 `complete`；`parent_id`、`error_code`、`connection`、`persona` 缺省 null；`system_prompt` 缺省空字串。分身訊息不保存分身提示詞全文。

`private_token_ids` 只驗證結構化參照，缺少仍為空集合；已提供的每項必須存在於 `replacements`，不掃描字面代號推斷參照。輸入、編輯備份及訊息區間使用 UTF-16 座標，須非負、起點小於終點且不超過對應原文長度，不裁切後接受。編輯備份的 `text`、`ranges` 必要，`image_ids` 可選且缺省空清單。圖片項目的 `id`、`mime_type` 必要。

不可讀草稿仍以清單項目保留 ID 與錯誤，使用者可重試或明確刪除；不製造空白聊天物件，不因單一壞檔隱藏其他工作。

### 日記整理 JSON

| 欄位 | 必要／可選與缺省 |
|------|------|
| `version`、`source`、`connection`、`stage` | 必要，版本為整數 1；來源含日記 ID、日記庫、日期、建立／更新時間、標籤、內文、附件，標題可為 null |
| `ranges`、`originals`、`protected_source` | 必要；隱藏區間、原文對照與代號化來源 |
| `person_tokens`、`token_surfaces` | 可選，缺省空物件；對照的代號必須存在於 `originals` |
| `turns`、`root_turn`、`selected_children` | 必要；需求與回覆分支，根回合可為 null |
| `organized_body`、`generation_reply`、`editing_turn`、`composer_backup` | 可選，缺省 null；候選稿的保護代號須完整，修改說明不列為聊天回合 |
| `generation_interrupted`、`composer`、`composer_ranges` | 必要；中斷旗標、未送出文字與 UTF-16 隱藏區間 |

回合的 `user`、`reply`、`interrupted` 必要；`parent` 可為 null，`surfaces` 缺省空物件。輸入備份沿用聊天的 `text`、`ranges`、可選 `image_ids`。

對照還原與候選採用只限原文，以及目前分支的使用者需求。結構完整但範圍不符的舊候選可以讀取，畫面不顯示，保存與套用必須拒絕。返回聊天才清除候選並續用需求。`generation_reply` 與候選一起保存，手動修改或返回聊天時清除，不進正式日記與備份。套用中斷恢復依來源與目標內容辨識，不靠改寫格式或重建人物資料。

### 分身與匯入 JSON

| 層級 | 必要／可選與缺省 |
|------|------|
| 分身狀態 | `schema_version`、`vault_id`、`person_id`、`persona_id`、`status` 必要；`cards`、`draft` 可為 null；狀態只接受 normal／deleting |
| 正式卡片 | `memory`、`tone` 同時存在，各含必要 `text`、`person_tokens`、`updated_at`、`selected_diary_ids` |
| 草稿 | `target`、`step`、`base_updated_at`、`hide_people`、`diaries`、`chats`、`card_hidden_ranges` 必要；`include_current` 缺省空物件；`manual_edit` 缺省 false；`connection_id`、`model`、`candidate` 缺省 null |
| 日記來源 | `entry_id`、`body_hash`、`needs_review` 必要；`hidden_ranges` 缺省空清單；正文變動後需重新檢查 |
| 聊天來源 | `import_id`、`content_id`、`excluded`、`hidden` 必要；`from_date`、`to_date` 缺省 null |
| 匯入內容 | `schema_version`、`vault_id`、`person_id`、`persona_id`、`import_id`、`imported_at`、`speakers`、`messages` 必要；`content_id` 只在狀態指標、檔名及加密身分，不重複寫正文 |
| 說話者 | `id`、`label`、`role` 必要；未指定角色保存 unknown |
| 匯入訊息 | `id`、`text`、`sent_at_local`、`system`、`quote_ranges` 必要；系統訊息的 `speaker_id` 可為 null |

`include_current` 以本次目標卡片名稱對應布林值，缺欄位或未列出表示不帶入。候選內容的 `text`、`person_tokens` 必要；草稿允許編輯途中不完整，正式提交時完整驗證目標卡片。分身區間除 UTF-16 界限外還須對齊 grapheme。訊息角色、來源參照與日期篩選不可依未提供的內容推測。

### 遠端清理 JSON 與金鑰維護

遠端清理保留既有 `{config, files}`，不新增格式版本。`config` 為必要連線快照；`files` 為必要清單，每項的 `id`、`uri` 都是必要字串。掃描、追加及未完成聊天判斷一律處理主檔、`.previous`、`.tmp`；未完成聊天的圖片不得被全域清理刪除。清理回寫重新讀取最新紀錄，只移除本次確定成功刪除的項目。

新復原金鑰輪替及裝置重新包裝，在寫入新的進行中旗標或 pending 前，先檢查分身。

正確復原金鑰仍可建立僅含記憶體復原金鑰的存取工作階段，讓使用者處理待重建分身。此時不建立新的裝置信任，也不啟用舊副本。缺主檔而存在替換副本時停止，不自動啟用舊分身。

只有實際中斷的工作，才可依經驗證的 pending 或既有重新包裝旗標恢復。候選須先核對日記庫、檔案身分、內容類型與加密認證。輪替掃描涵蓋 `.enc.tmp`，不把舊金鑰下的暫存檔遺留在外。若替換副本無法清理，金鑰維護保留恢復狀態，不提前宣布整個換鑰完成。

`rewrap_in_progress` 在索引中記錄裝置重新包裝的中斷狀態；復原金鑰輪替另有 `recovery_rotation.pending`。未完成輪替的恢復可同時讀取新舊金鑰保護的檔案，再回到 pending 所記錄的舊世代，不等於繼續完成新金鑰輪替。pending 與 metadata 已提交狀態相符時，也須先驗證現有金鑰才可清除殘留。排錯時不要先刪 pending、替換副本或整個索引。

輪替 pending 必須是 `recovery_rotation_pending` 身分及 `application/vnd.quill-diary.recovery-rotation` 類型；AEAD 只保證檔頭未遭竄改，不能代替預期身分核對。身分不符保留現場，不當作 stale pending 清除。

裝置包裝記錄的 `slot_id`、`nonce`、`ciphertext` 為必要非空字串；nonce 必須為合法 base64 的 12 bytes，密文必須包含 AES-GCM tag。`format_version` 缺省 1，已提供時必須是整數 1；`wrapped_at` 缺少時為 epoch，已提供時須為合法時間；`platform` 缺省空字串，已提供時須為字串。裝置資訊的槽位亦為必要非空字串。損壞記錄導向復原金鑰重新建立，不刪正式日記。

## 完整備份包含與排除

ZIP 名為 `backup_YYYY-MM-DD_HH-MM-SS.zip`（修復前為 `backup_before_repair_...`）。外層不加密，根目錄是 `vault/` 的內容，不含 `vault` 這層目錄名。

檔案範圍以上方路徑表為準：一般正式檔複製既有密文，分身另取已發布內容重新加密。索引、一般草稿、裝置偏好、安全儲存與系統暫存都在日記庫外，不納入 ZIP；日記庫內的未完成工作則依排除目錄過濾。API Key 不在 ZIP。

正常正式格式中的明文成員為 `recovery.json`、`tag_styles.json`、`pinned_entries.json`。目前一般日記庫打包採排除規則，並非只允許這些檔案的白名單；任意放進 `vault/` 的其他檔案也可能被納入，不能把這份目錄表當成對外來檔案的過濾保證。

ZIP 解壓的項目數、未壓縮大小與壓縮比限制，以及樣本金鑰驗證，見[備份檢查與還原](../功能/備份與還原.md#完整備份檢查)。結構檢查不會逐檔解密，也不保證所有日記都可讀。

Markdown／HTML 只匯出正式日記，不含聊天、人物、AI 設定與 API Key。
