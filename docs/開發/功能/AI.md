# AI

手機直接連線使用者指定的服務，開發者不提供 AI 中繼伺服器。聊天日記與日記整理共用 AI 連線、聊天介面、模型選單、請求預覽及生成進度元件；正式聊天與整理暫存分開保存。「啟用 AI 功能」與人物隱藏是共用的全域開關，分別寫在設定檔頂層 `ai_enabled` 與 `hide_people`。提示詞覆寫有內容時才寫進 `chat_diary` 與 `diary_organization`。`chat_diary` 也可記住下一則新聊天的夥伴。文字區間與人物區間在 [`private_text.dart`](../../../lib/domain/ai/private_text.dart)，輸入快照在 [`ai_composer_snapshot.dart`](../../../lib/domain/ai/ai_composer_snapshot.dart)。

使用者資料如何傳送、保留與刪除的公開承諾見[隱私權政策](../../privacy-policy.md#ai-服務與聊天資料)；本文件只記錄實作與維護規則。

AI 開關先更新畫面，再保存到加密設定；背景讀取與失敗回呼僅在原工作階段及操作仍有效時更新開關，避免舊設定覆蓋最新切換。寫入失敗還原最後已成功保存的值。

## 共用

### 訊息呈現

聊天室、日記整理與請求預覽共用 `AiMessageView` 的左右對齊、泡泡寬度、圓角、內距、配色、圖片排列與隱藏高亮。角色標籤、尚未送出狀態及聊天操作由各頁提供。使用者訊息及請求預覽使用純文字；聊天室與整理的 AI 回覆保留 Markdown，預覽顯示實際外送的原始語法及代號。

### 輸入人物名稱

聊天日記與日記整理的輸入框共用 `@`／`＠` 人物建議。依姓名及別名搜尋，選取後插入指定的日記稱呼，移除 `@` 且不自動加空白；仍是一般文字，送出時沿用人物隱藏設定。手動隱藏的文字區間會隨替換調整。

人物建議以 chip 列放在輸入框外側下方、鍵盤上方，不另加底條，與輸入框保持間距，可左右滑動，也支援上下方向鍵、Enter 選取及 Esc 關閉；中文組字期間不攔截確認鍵。名冊僅在查詢作用中訂閱，不額外啟動人物統計；已有統計才沿用排序。名冊為空或沒有符合項目時，可預填查詢文字開啟人物新增表單，儲存後回填有效的原查詢。忙碌時收起建議；背景、鎖定、切換對話或離頁時關閉本次人物表單並忽略過期回傳。已完成聊天沒有輸入區。

### 連線與模型

| 提供商 | 協定與圖片傳送 |
|------|------|
| OpenAI | Responses；圖片經 Files API 上傳後引用 |
| Claude | Messages；圖片經 Files API 上傳後引用 |
| Gemini | GenerateContent；圖片經 Files API 上傳後引用 |
| xAI | Chat Completions；圖片以內嵌 data URL 傳送 |
| Custom（多組具名連線） | Chat Completions、Responses、Claude Messages、Gemini GenerateContent 或 Ollama Chat；圖片使用所選協定的內嵌格式 |

供應商順序、官方模型、預設開關及思考強度由 [`ai_catalog.dart`](../../../lib/domain/ai/ai_catalog.dart) 管理，設定與請求欄位轉換在 [`ai_connection_settings.dart`](../../../lib/domain/ai/ai_connection_settings.dart)。

- 新供應商套用目錄預設；已看過的模型維持開關，未看過的新模型才套預設。移除舊官方模型後，若原本開著且沒有其他啟用模型，才啟用新預設；單純移除目錄項目不會重新啟用已關閉的現有模型，新增目錄項目仍依前述規則處理。目錄外且記在 `added_models` 的名稱保留為手動模型；只在 `enabled_models` 的非目錄名稱會被整理掉。
- 設定依序顯示說明、隱藏人物姓名、聊天日記、日記整理、模型、官方 API 及自訂連線。模型卡片分開顯示名稱、供應商與思考設定，以底色及開關辨識啟用狀態；手動模型的刪除 X 位於開關左側。主列表在開啟設定、加入模型或新增連線時重排，先列啟用模型，再依供應商、連線建立順序、目錄及手動加入順序排列，顯示前 10 筆；重複加入會啟用既有模型並重排，單獨切換開關或 Thinking 時維持位置。「更多」依供應商及自訂連線分區，區內依版本數字由大到小、再依名稱排列。變更按「儲存」才保存，取消則捨棄。
- Thinking 膠囊按鈕顯示目前思考強度，選單只列該模型支援的選項，固定模式不顯示按鈕。主列表與「更多」共用設定，窄畫面或大字級時控制項換行。`thinking_levels` 依模型保存偏離預設的選擇，連線測試、聊天與生成使用同一轉換規則。
- OpenAI、Claude、Gemini、xAI 需有 API Key；Custom 有網址即可。沒有可選模型時顯示紅字，儲存後仍留在設定頁。各供應商的連線測試互相獨立。
- 聊天的浮動選單比較上下可用空間，朝較大的一側展開。寬度依內容決定，並受螢幕可用寬度限制；高度以該側可用空間為限。長名稱換行、項目過多時可捲動，目前模型以勾號標示。點外部、按 Esc、進入背景或鎖定會關閉選單，晚到的設定不會重新開啟。選單只列啟用且連得上的模型；目前正在用、但已關閉或清掉金鑰的模型留在最後。切換會更新本則聊天及下一則新聊天的預設，其他既有聊天不變。
- Custom 的 Base URL 可含 `/v1`、`/v1beta` 或 `/api`；原生協定補齊需要的前綴，已有版本路徑不重複加入。Chat Completions 須自行包含服務要求的前綴。Ollama 圖片能力透過 `/api/show` 查詢，不依模型名稱猜測。

API Key 只留在裝置安全儲存。每組 Custom 連線依穩定連線 ID 與正規化網址分開保存；同網址可使用不同 Key。換網址先清空欄位，再讀取該連線在新目的地的金鑰；清空後儲存即可刪除。服務、具名連線、模型、思考設定、網址、協定、Claude Workspace ID、自訂提示詞、AI 功能開關及人物隱藏寫在加密日記庫，會隨完整備份還原。儲存位置與備份邊界見[本機儲存](../資料/本機儲存.md)。

自訂區以可收合卡片管理多組連線，同時展開一組。名稱不可空白，使用中的名稱不可重複。聊天選項依連線 ID、目的地與模型區分，聊天標籤顯示「精簡網址／模型」，省略 http(s):// 並保留埠號與 API 路徑；相同標籤才在第二行補連線名稱。完整網址與名稱保留在提示文字及無障礙標籤，設定列表直接顯示連線名稱。相同網址或同名模型也不會合併。新增連線不切換有效的聊天預設；選擇聊天模型才更新下一篇使用的連線與模型。

刪除自訂連線先顯示全 App 共用的紅色刪除確認，外層儲存後直接移除設定，並刪除該連線各目的地的本機 API Key，不封存或提供恢復；取消外層設定、改名或只換網址不會刪除金鑰。既有聊天仍保留原連線快照，但之後的請求與遠端清理不再持有該金鑰；從原聊天開啟設定時，仍可為該快照重新輸入金鑰。被刪除草稿尚未儲存的 Key 變更不會寫入。移除全域預設後改選第一組可用連線；沒有可用連線時需完成設定。從聊天室開啟設定時，編輯其他連線不會將目前聊天換到全域預設；原目的地已異於保存設定時，保留原聊天快照，另提供該目的地的金鑰欄位。

連線測試送一則「Reply with OK.」的非串流請求，最多等待 45 秒。一般請求的標頭與串流／非串流本文都有五分鐘逾時，本文逾時會中止連線。串流一旦收到該協定的結束事件，或 OpenAI 相容格式的 `[DONE]`，就停止讀取，不等連線自行關閉，避免完成後仍被後續等候或逾時清掉。錯誤不顯示服務商回應本文。

協定、Thinking、聊天模型與人物排序共用等寬選單。開啟「隱藏人物姓名」時，已知姓名會在輸入中高亮，外送時換成人物代號。手動隱藏區間另行管理。

「提示詞」集中顯示聊天日記、日記整理、AI 分身與連線測試。前三組首列可預覽完整組合，包括整理捷徑、分身各更新目標及分批與重整指令。可自訂項目標示內建或自訂，編輯時可查閱內建原文。套用更新設定草稿，儲存才生效。各功能的請求預覽可核對實際外送材料。

### Thinking 參數的來源與限制

模型目錄人工指定每個官方模型的 Thinking profile、可選強度與預設值，再由 `thinkingRequestFields()` 轉成請求欄位。支援範圍應依該模型與 API 的官方文件維護，例如 [OpenAI reasoning effort](https://developers.openai.com/api/docs/models/gpt-6.1-terra)、[Claude Sonnet 5.5 thinking](https://platform.claude.com/docs/en/models/sonnet-5-5/whats-new-sonnet-5-5)、[xAI reasoning](https://docs.x.ai/developers/model-capabilities/text/reasoning) 及 [Ollama thinking](https://docs.ollama.com/capabilities/thinking)。App 的預設強度與四個介面選項是產品設定，不代表供應商的預設或全部支援值。

自訂連線新加入的模型預設不傳送 Thinking 參數；既有模型與重複加入保留原設定。手動模型可從 Thinking 選單開啟設定，沿用關閉／低／中／高，停用不支援的檔位並指定有效預設。傳送方式包括沿用協定、不傳送參數及自訂 JSON。自訂模式以目前協定對照作為初始欄位，既有自訂 JSON 則原樣載入；切換模式保留尚未套用的輸入。自訂 JSON 會併入請求，可能影響回覆長度和費用。沒有覆寫時仍使用既有協定規則，不自動查詢或確認模型能力。

自訂 JSON 會直接顯示各強度的編輯欄位。每個啟用的強度可填寫 JSON 物件，`{}` 代表省略該強度的額外參數。視窗上方會預覽預設強度的參數。不傳送模式不提供強度選項，但仍可開啟設定。Ollama 的協定預設以布林值控制 Thinking；需要 low／medium／high 等模型專用格式時，使用自訂 JSON 設定。

`AiModelThinkingOverride` 深度凍結 JSON，覆寫保存在各連線的 `thinking_overrides`，選取強度仍用 `thinking_levels`。進階請求覆寫取代協定產生的 Thinking 欄位，再遞迴合併到請求；禁止覆寫 model、messages、input、instructions、contents、system、systemInstruction、stream 與 store。其餘欄位（例如 max_tokens）會一併送出，可能改變輸出或費用。無效輸入留在欄位並阻止套用，後端拒絕時不自動改參數重試。

設定視窗的「套用」只改外層草稿，外層「儲存」才保存；取消不保存。連線測試、聊天與生成使用相同解析規則。有效參數、連線或 Key 改變時重建客戶端；JSON 鍵順序改變不重建。舊訊息快照保留當時的連線與該模型對照。

自動測試驗證目錄、參數映射及模擬請求，不會逐一呼叫真實模型；驗證範圍與限制見[驗證](#驗證)。

### 傳輸與協定

Custom 的 HTTPS 可用指定主機；HTTP 只允許 loopback、IPv4 私有網段及 IPv6 ULA，拒絕主機名稱、link-local 與公網 HTTP。送憑證前由 `validateAiEndpoint` 驗證，不跟隨重新導向、不略過 TLS 驗證。Android 設定見[權限與資料揭露](../google/Android-權限與資料揭露.md)。

儲存包含自訂 HTTP 的設定時，先確認明文傳輸風險。取消保留編輯內容。

解壓後的一般回應上限為 16 MiB。SSE 上限為單行 1 MiB、單事件 4 MiB、單次 32 MiB。等待回應標頭或本文閒置達 60 秒，或整次請求達 10 分鐘時，停止當次請求。取消及超限也只清理當次連線。

Responses 送出 `store: false`，不代表零留存；Custom 的資料使用與留存由該服務決定。API 參考：[OpenAI 圖片](https://developers.openai.com/api/docs/guides/images-vision)、[Responses](https://developers.openai.com/api/reference/resources/responses/methods/create)、[Claude Messages](https://platform.claude.com/docs/en/api/messages/create)、[Gemini](https://ai.google.dev/api/models)、[Ollama](https://docs.ollama.com/api)。

## 聊天日記

首頁按「新增日記」後，每次選擇直接寫日記或聊天日記；手機使用底部卡片面板，600px 以上使用最大 480px 的中央視窗。選擇前不建立日記或聊天草稿，取消會保留首頁搜尋與篩選；鎖定、切換日記庫或進入背景時關閉選擇器。聊天仍沿用既有 AI 連線檢查與設定流程。未完成聊天列在首頁；正式儲存後可從日記檢視頁開啟完成聊天。

### 預設提示詞與生成

聊天依序組合角色、固定規則、對話引導及預設個性。分身使用自己的角色與內建引導，並附人物代號、記憶和風格。自訂引導由兩種夥伴共用。目前分身的歷史回覆維持原話，其他夥伴的回覆附說話者標籤。分身的基本提示詞與請求共用 `personaFixedInstructions`。

日記生成先套用固定的來源、事實、隱私、待辦與 Markdown 規則，再套用內建或自訂引導。引導可調整語氣、篇幅、組織及語言。在固定規則允許的範圍內，以使用者對這篇日記的明確要求為準。

提示詞內容在 `lib/l10n/*.arb`，依 App 語系使用台灣繁體中文或英文。單次聊天換語言不影響日記預設語言。自訂內容保留原字，還原只清除該項覆寫。設定頁、請求預覽和實際送出共用 `resolveChatDiaryPrompt` 與[分身提示詞](../../../lib/application/persona/persona_prompts.dart)。歷史訊息的系統提示詞不追加外送。連線測試與設定頁共用同一則短訊息。

聊天設定使用 `ChatDiaryPromptSettings`，分別覆寫個性、對話引導與生成引導；日記整理使用 `DiaryOrganizationPromptSettings`。空白覆寫的保存方式與既有完整提示詞不搬移的規則見[本機儲存](../資料/本機儲存.md#設定與連線快照)；有內容的文字不裁切、不自動拆分。既有完整生成提示詞外送時作為固定規則後的引導。

內建提示詞將來源、任務、限制與輸出分開說明；繁中與英文採相同規則。一般聊天使用短段落，只有必要的多個重點才用單層條列；需要解釋或協助時不受一般回覆句數限制。

預設日記內文以自然段落為主，必要時才使用單層列表或真正的待辦，內文不用 Markdown 標題、粗斜體、表格或圍欄；首行 `# 標題` 僅用來擷取獨立的日記標題。

預設夥伴先回應對方已說的細節，再補一個相關角度或問一句好回答的開放問題。場景、感受與結果由使用者補充。抱怨先回應困擾，收到明確請求再展開建議或安排。分身依風格卡接話，並以記憶中最近一次可確認的進度回答往事。

生成資料以 `user_turns` 保留目前分支的使用者原話。`assistant_context` 只含緊接在使用者訊息前的完整 AI 回覆，以 `for_user_turn` 標明所對應的訊息，用來理解短答。日記事實採使用者已確認的內容與可辨識的圖片細節。前後對象不同時，分別寫清楚原本差點發生的事和後來完成的行動。資料沒有訊息時間，無從換算的相對日期照原話保留。素材短時可以只寫一句內文，有內容就加上標題。無可記錄的內容時回傳空字串。

「完整 JSON」在提示詞上方，以共用格式呈現聊天與生成請求的模型、參數、遮罩後文字及照片編號。提示詞以對應的卡片標題表示。草稿在聊天請求中標記為 `pending`。生成摘要依同一份生成資料統計訊息則數。

| 使用者意圖 | 生成方式 |
|------|------|
| 經歷或感受 | 第一人稱自然段落，保留用字、情緒與不確定性 |
| 構想、規劃，或以提問提出的需求 | 連貫的想法紀錄；必要時用簡短小標題。未定事項保持未定 |
| 明確要記得做、可辨識完成的事項 | `- [ ]` 待辦 |
| 明確追蹤的待辦已完成，或要求標示完成 | `- [x]`；一般已發生的事仍用敘述 |
| 已追蹤事項延期或取消 | 延期保留最新時間與未完成狀態；取消以敘述保留，不標成完成 |
| 願望、習慣目標、功能需求或討論中的方案 | 一般文字；明確要求列為待辦才轉換 |
| 經歷、構想與待辦混合 | 依內容混合段落與單層清單，必要主題標籤用普通文字，不套固定作文或會議紀錄 |

生成閱讀整段對話，不因最後一輪只是補充就丟掉前文，並遵守最新更正、長度與排除要求。簡短的確認、否定或修改要保留。AI 單方面提出的選項，以及沒有反駁的猜測，不寫成使用者的決定或未決問題；使用者明確想留下的知識或討論成果可以記。圖片只採用清楚可見且相關的資訊，不推定身分或拍攝情境；人物與私密代號逐字保留，不輸出對照表或附件路徑。模型只輸出一級標題及 Markdown 成品，無可記內容時輸出空字串。

`generate()` 回傳 `ChatDiaryGenerationResult`：成功提交為 `generated`，正常結束但內容空白為 `empty`，失敗、取消或無法開始為 `notGenerated`。空內容留在聊天室顯示提示，保留原草稿、附件、來源與快照；不建立私密補記或交接編輯器。傳輸錯誤維持原錯誤處理。

聊天室儲存新設定會停止舊請求並保留進度。API Key、連線、有效思考強度或思考請求欄位改變時，下次請求重新建立客戶端。一般回覆保存當時連線與有效提示詞，生成另存其快照。分身回覆只保存人物與分身識別，不保存分身提示詞。聊天格式仍是第 1 版；`selected_persona`、`persona_participants` 與訊息上的 `persona` 沒有就不寫。

### AI 分身

分身以人物記憶與聊天風格組成提示詞，不進行模型微調。記憶保留有明確支持的事件、偏好、習慣及人物關係，區分本人自述、使用者觀察與他人轉述；單次行為不概括成習慣，未解矛盾不只因來源較新就定論。一位人物可有一份正式分身及一份未完成更新；從人物詳細頁管理，在聊天室選擇夥伴。管理路由為 `/persona/:personId`。

在聊天室換成某位分身或改回預設夥伴時，才記住這個選擇，之後新開的聊天沿用。只打開、重讀或完成既有聊天不會改寫；其他聊天仍用自己保存的夥伴。分身被刪除，或新聊天發現已選分身不可用時，該聊天回到預設夥伴並顯示既有提示，同時清掉記住的選擇，避免之後每則新聊天重複提示。試用分身不寫入這個選擇。

#### 建立與更新

首次建立同時產生人物記憶與聊天風格；之後可只更新其中一項，另一項保持原值。正式內容保存各自的更新時間與選取日記 ID，供下次更新沿用選取及檢查衝突。草稿不保存日記全文，重新載入時會檢查正文雜湊；來源已變動時，清除舊隱藏區間並要求重新檢查。

更新沿用上次選取的日記。舊記憶與舊風格各自勾選是否帶入：新建預設不勾選，繼續草稿保留原選擇。未勾選的不外送，證據不足時也不自動補回。帶入舊記憶可能保留已取消選取日記裡的資訊，材料頁會先說明。勾選與隱藏分開，查看或標記舊卡片不會自動勾選。材料或設定變動後，確認快照失效，須重新準備。

準備材料頁依序是隱藏設定、匯入聊天與日記。「下一步」進入「確認內容」，此時不連線。確認頁先列已勾選的舊卡片，再列聊天與日記：要外送的顯示遮蔽後文字，本機保留的顯示實際內容，並用標題區分；未勾選的不列出。系統提示詞與分批整理提示詞預設收合。分批外送提醒直接顯示。「開始整理」才執行。

連線依草稿的連線 ID 與模型解析。官方連線沿用目錄預設，已移除的自訂連線會阻止送出。只有舊卡可用時，直接在本機建立候選。完全未選材料且未帶入舊卡時停止生成。長材料由同一服務分批提取，再整合成候選卡片。

風格取自分身對象的可見 `style_text` 和選入的可見日記。日記支持用字、句長與節奏。其他人的發言、引用和轉述提供語境。風格卡描述可隨情境調整的說法。日記全部隱藏，且找不到本人可見原話時，風格卡由本機按勾選保留舊內容或使用中性文字。若同時更新記憶，外送只請求記憶。

整合只回傳目標欄位的字串。空字串由本機依勾選保留舊卡或使用中性文字。格式、代號與輸出語言須符合檢查。繁中候選若主要敘述明顯是英文，會在審閱前回報錯誤。記憶和風格各以 8,000 和 4,000 個 UTF-16 單位為上限。超長欄位以同一份證據重整一次，目標分別是 7,200 和 3,600。重整失敗時保留草稿和正式卡片。

人物記憶以「YYYY-MM-DD：事件」逐項記錄。日期不明寫「時間未詳」，偏好、習慣和關係可省略日期。同一事件依最新證據合併，明確更正只保留新值。日期以原發言為基準，遇到「昨天」「昨晚」時可用請求內的 `previous_local_date`。引用與轉述採原說話者的時間。

分批預覽與實際請求都以 UTF-16 單位計算長度，包含 JSON 標點與跳脫。`fragment` 上限為 9,000，完整請求上限為 16,000。原始材料安全切段並保留字元與代號。進入精簡輪次後，以完整證據項目合批，去除同類且文字相同的項目。已選的遮蔽舊卡若讓剩餘容量不足一批證據，會標為 `prior_card` 與新材料一起精簡。

中間證據以 `memory`、`tone` 字串陣列回傳，每批驗證格式、代號與 1,500 單位上限。中間證據只留在本次工作。格式或長度錯誤時，每個工作最多用同一批遮蔽材料重送一次。每輪必須縮短完整請求，最多四輪。容量仍不足時保留草稿並說明原因。進度按當輪總批數計算，只計入驗收通過的批次，等待時間與批次進度同列。

生成結果必須審閱並儲存才啟用；審閱時可與目前已儲存內容比較，明確選擇保留目前仍可把候選改回已儲存文字，不受帶入勾選限制，仍需儲存才生效；捨棄結果會清除候選與請求快照，回到準備材料。停止、鎖定、分身刪除重建或目標卡片已在別處更新時，舊工作失效。確認快照只保留於記憶體，重新開啟或快照失效時直接回到準備材料，保留已選材料、文字修改、帶入選擇與隱藏設定；已生成的審閱候選仍保留，不自動重新送出。舊卡片查看與比較面板會在真正進入背景或鎖定時關閉。試聊只使用候選內容，不加入正式聊天，關閉或鎖定後清除。

分身頁初始化及操作共用錯誤處理。AI 設定不可讀時提供既有設定檢查與重建入口，完成後返回原分身草稿；失效工作階段的錯誤不影響目前畫面。

#### 匯入聊天與隱藏

可匯入 LINE 文字檔、Messenger 一般匯出與端對端加密備份的 JSON、Instagram 訊息 JSON。一次可選多個檔案，單次選取合計不超過 16 MB。匯入區的說明按鈕列出各平台的匯出步驟與限制。沒有對上這些格式的檔案整份保留，不切成訊息，也不套用日期範圍。

內建辨識失敗時，對話框顯示全文。使用者反白標記要隱藏的片段，並可新增人名、標成自己或目標對象。這些人名只用於遮罩與標示該人是否出現，不逐句指定說話者，也不當成聊天風格的直接證據。目標對象的名字換成這位人物的代號；其他新增的名字換成匯入代號。原始檔不送出。LINE 解析逐行容錯，略過的行數會顯示。重複訊息以說話者、秒級時間與文字前 64 個 UTF-16 code units 合併。

內建格式匯入的聊天需指定說話者角色，並依日期選擇納入範圍。原文匯入沒有日期篩選，之後仍可改隱藏區間與人名角色。日期編輯器保留說話者與時間，允許修改文字、隱藏片段及逐則刪除，刪除按鈕使用錯誤色。「套用」一起保存文字、隱藏與刪除；空白訊息一併移除並清掉其隱藏、排除設定。「取消」或關閉不套用變更。隱藏與引用區間隨文字調整，引用內容不作為聊天風格的證據。LINE 的引用行仍只在 LINE 文字解析中標記。

分身草稿的隱藏姓名開關初始沿用 AI 設定，之後獨立調整。開啟時把已登錄姓名換成人物代號，本機閱讀仍可顯示姓名；關閉時可外送名冊姓名。確認頁的外送材料呈現實際外送文字，以底色標示人物代號與私密代號；標示本機保留的卡片不加入請求。內建格式的匯入聊天依日期排序，同一天合併成一張卡片，保留每則說話者與時間；跨匯入來源時另標來源。原文匯入另成一塊，不依日期合併。這只改變閱讀排版，不調整請求材料的內容或順序。

手動隱藏、自動個資與無法確定的姓名都換成 `{{PRI_NN}}`。同一次生成裡，相同原文重用同一代號，不同原文使用不同代號。生成與分批提示詞要求逐字保留人物代號，且不要把私密代號寫進結果；輸出驗證拒絕含有私密代號的候選。人物代號必須保留完整格式與原指代。

#### 儲存與備份

材料文字與隱藏區間透過同一次狀態提交切換；儲存失敗沿用舊內容，成功後才更新記憶體。正式儲存會清除草稿及匯入材料；檔案清理失敗另標記待清理，不把成功提交回報為失敗。

本機修改平常延遲 400 毫秒保存。鎖定與控制器釋放時立即擷取最後待存草稿，排入加密寫入後清除畫面資料，不等待寫入才鎖定；生成晚到結果仍失效。載入取消會重設載入狀態，解鎖後可重新載入，舊工作不能解除新工作的載入狀態。寫入失敗保留磁碟最後有效版本，失效回呼不更新新畫面；不自動重試 AI 請求。

正式分身以加密檔納入本機與 Drive 完整備份，未完成更新與匯入聊天排除；可攜匯出不包含分身。還原後取得備份當下的正式內容。檔案路徑、格式版本、提交順序與恢復限制集中於[本機儲存](../資料/本機儲存.md#人物分身提交與備份)。

### 訊息與分支

- 固定歡迎訊息只在本機顯示，不進入請求或日記事實，續聊沿用原開場。
- `parentId` 建立訊息樹，`selectedChildren` 保存版本選取，`activeMessages` 為目前路徑。編輯重送與重新回覆新增版本；切換版本不連線。沒有父訊息、錯誤或該則連線時，不寫 `parent_id`、`error_code`、`connection`。尚未生成或編輯時，不寫 `generation_connection`、`generated_entry_id`、`generated_from_message_id`、`generated_draft_signature`、`editing_message_id`、`edit_backup`。`edit_backup` 沒有圖片時不寫 `image_ids`。
- 新訊息、編輯重送與重新回覆都以開始請求時選取的夥伴組合提示詞，並將同一人物識別保存於新回覆；切換分身或回到預設夥伴後，重新回覆也會跟著切換。舊版本保留原本的人物識別與內容。
- 編輯以 `editBackup` 保存原輸入、私密區間及附件，取消或送出後還原。圖片引用涵蓋全部分支、輸入與編輯備份。
- 請求預覽同時列出可收合的聊天系統提示詞與生成系統提示詞，不切換整頁。展開後若內容超出卡片，右側顯示不可拖曳的位置提示。下方訊息是聊天請求：包含目前上下文與待送內容，編輯時只取目標訊息以前。生成系統提示詞另列；實際生成只含已送出的目前分支，並打包為對話 JSON，不帶待送文字或圖片。兩者排除失敗或中斷的 AI 回覆。
- 訊息列表延遲建立，接近底部才跟隨串流；讀舊內容時保留位置。等待動畫尊重減少動態效果設定。
- 請求期間停用功能操作，仍可捲動與返回。失敗及中斷回覆留在原位供重試；完成聊天唯讀，仍可切換版本。
- 離開聊天室或切換 App 時，進行中的請求繼續到保存完成，返回時接回同一請求。進入 `hidden` 或 `paused` 時關閉圖片、預覽與選單。鎖定或工作階段失效時停止請求、清除聊天與輸入，保留加密進度。
- 生成狀態由聊天室與首頁草稿卡共用，依實際事件顯示準備、等待模型、撰寫及儲存階段，不估算百分比。狀態卡只提供停止生成，使用者仍可按返回離頁或切換 App。首頁只顯示狀態標籤。失敗原因與重新生成、草稿狀態與查看草稿，都在聊天室訊息列表頂端的同一條提示，一次只出現一種。
- 聊天回覆與日記生成都只送一次。連線中斷或程序被系統終止後不自動重送；重新開啟沿用已保存的對話與草稿，工作狀態不跨程序保存。生成不使用前景服務或系統通知。鎖定與晚到結果見[解鎖與會話](../安全/解鎖與會話.md)。
- 生成成功先提交草稿，真正開啟編輯器才交接。只有持續留在原聊天室且未切到背景時才自動開啟；其餘情況由首頁或聊天室查看，不強制導頁。
- 連點只啟動一次流程。等待保存時若已離頁則不交接編輯器，也不阻擋後續聊天。點擊首頁草稿卡進入聊天室後才重試或查看草稿。
- 首次保存及請求結束後更新首頁草稿；刪除聊天先取消作業並排空待寫入，再刪除，晚到內容不能重建草稿。

### 文字隱私與私密補記

手動隱藏、自動個資辨識與人物姓名比對共用 [`PrivacyTextProcessor`](../../../lib/domain/ai/privacy_text_processor.dart)。功能層只決定來源、保存與採用。手動選取不連帶遮蔽其他相同原文；與自動辨識重疊時手動優先，外圍仍自動遮蔽，且不納入私密補記。人物只在送出當下比對名冊，區間記在訊息上，之後改名冊不再改已送出的訊息。有效提示詞仍會替換目前分支已標記的原文。名冊讀取失敗會停止預覽與請求，不以空名冊略過。

本機與外送共用 `{{PER_NN}}`、`{{PRI_NN}}`，規則見[本機儲存](../資料/本機儲存.md#各操作的掃描範圍)。個資辨識在 [`sensitive_text.dart`](../../../lib/domain/ai/sensitive_text.dart)：台灣手機、市話、Email、通過檢查碼的身分證與信用卡，以及明確憑證。地址、銀行帳號、LINE ID、統編及未知姓名仍需手動隱藏。同名多重命中不自動選人；匯入匿名識別依來源隔離。

所有 AI 文字請求經過 [`prepareAiRequest`](../../../lib/domain/ai/ai_request.dart)，再由 `AiClient.reply` 傳送。提示詞、日記、目前分支與進階 JSON 字串都會檢查；明確憑證欄位遮蔽整個值。準備好的請求固定目的地與外送文字，預覽與各協定共用。連線測試、模型查詢與遠端檔案刪除不帶日記。未知代號不綁定原文，由各功能原有驗證處理。

輸入框與材料編輯用 `PrivateTextController`，經 `privacyHighlightRanges` 合併手動區間與自動命中；自動命中不寫進手動區間，因此沒有私密補記資格。對自動標出的個資或人名按「取消隱藏」，只讓這一處以明文外送，同一人名的其他出現仍遮罩，區間存在草稿；按「隱藏」可恢復。單一人名仍換成人物代號，多包其他文字或重名才用私密代號。已送出的訊息不回寫，續送沿用送出當下保存的取消區間；聊天泡泡只用訊息上保存的 `automatic_ranges`，不重新辨識。AI 回覆用 `restoredPrivateRanges` 只標實際還原的代號；整理回覆與正文同樣以 `organizationVisibleText` 還原顯示。呈現與還原都不改寫保存原文，也不把還原文字再送給模型。

生成後在手機還原目前分支。自動隱藏只在模型引用時還原；未被引用的手動隱藏仍附加到「私密補記」，AI 的排除要求不能阻止。其他分支不補入。只有目前分支已送出一般私密文字時，輸入區與生成預覽才提示這項規則。

分身材料的處理同上，回覆若含私密代號不得寫入候選。較長材料先在背景辨識，再切批外送。

隱私處理失敗保留輸入並停止該次請求，不以原文重試。錯誤不含原文或對照。圖片只清中繼資料，不辨識影像內容。以上不保證完整匿名。供應商政策見[隱私權政策](../../privacy-policy.md#ai-服務與聊天資料)。

### 圖片與清理

聊天保存原圖，選取時套用[圖片單檔上限](日記編輯器.md#附件)。一般編輯器的新圖片依個人化設定壓縮，生成交接沿用已保存的圖檔。傳送副本保留 JPEG／PNG／WebP／GIF 的原尺寸與壓縮像素、方向、色彩及動畫必要資料，移除私密與未知附屬區塊，包含動畫 WebP 影格。其他可解碼格式轉原尺寸 PNG，大型位元組清理在背景 isolate 執行。

使用 Files API 的提供商上傳後先保存遠端清理紀錄才發布快取。記錄失敗會嘗試刪除遠端檔，重試重新上傳。紀錄依連線快照分檔，不含 API Key；完成或刪除聊天後清理，失敗於之後進入 AI 功能時重試，未完成聊天的遠端圖片保留。重試只移除本次成功刪除的參照，不覆寫等待期間新增的紀錄。

移除引用及取消附圖時，晚到寫入仍須清除本機圖片與 `.previous`、`.tmp`。

### 草稿交接與完成聊天

一段聊天共用一份生成草稿。一級標題取為標題，其餘保留為內文；自訂輸出沒有一級標題時全作內文。`generatedFromMessageId` 記錄來源版本，切換分支或新增內容會提示草稿可能過期；人工編輯以內容指紋辨識，取代前先確認。

附件逐張解密暫存，依本機 ID 去重並保持首次送出順序。發布前再次檢查操作有效性，取消或失敗只清本次暫存；提交點一起更新來源、連線、提示詞與指紋，提交後離頁仍完成保存。

正式日記儲存成功後才保存完成聊天、刪除聊天草稿與解密預覽。中斷收尾在下次讀取草稿清單時補完，重複收尾可辨識已完成聊天。編輯器保存與 checkbox 持久化見[日記編輯器](日記編輯器.md)。

完成聊天只沿用正式附件，未收錄或已移除圖片顯示「圖片已刪除」。完成聊天沒有輸入區或「開啟日記」按鈕，按返回回到日記，重新進入時重讀附件。AI 與使用者訊息使用相同圓角與內距、不同底色；聊天與送出預覽的文字皆沿用一般日記內容的字型、字級與行高。送出預覽保留原始文字與私密代號供檢查；生成按鈕位於模型選擇右側，窄版依序為上方靠右的生成、下方靠左的模型。刪聊天不刪日記；刪日記會清相鄰聊天及恢復檔。改日期與修復搬移一起處理聊天，衝突保留來源並回報。備份流程見[備份與還原](備份與還原.md)，加密格式見[加密格式](../安全/加密格式.md)。

### 驗證

程式入口集中於[模組參考](../架構/模組參考.md)，測試分層見[測試手則](../../../test/test-handbook.md)。自動測試使用合成內容、mock、本機 HTTP 與測試日記庫，不呼叫付費 API，涵蓋模型目錄更新與思考參數、設定回寫、分支與隱私、生成草稿保護、取消清理、備份往返及畫面互動。

通過自動測試不等於已取得每個模型的線上相容性驗證；實際支援值仍需對照官方文件。模型實際寫作表現需另以繁中與英文合成對話驗收；連線及圖片可能計費，使用測試者自己的金鑰。


Google Play 額外回報及審查存取要求見[上架文件](../google/Google-Play-上架.md#ai-生成內容的送審缺口)，連線成功不代表送審條件已完成。

## 日記整理

日記檢視頁的 AI 選單提供「查看保留的對話」與「日記整理」。沒有保留聊天時，檢視項目停用；有整理草稿時改顯示「繼續整理」。讀不出來的整理草稿會刪除並改為新的整理，日記本體不動。手機使用底部面板，600px 以上使用中央對話框。

### 操作流程

1. 進入日記整理時，若目前連線缺少模型、必要網址或 API Key，自動開啟 AI 設定。設定完成後更新本次整理連線；取消後留在整理畫面，同次進入不重複彈出，也不送出 AI 請求。隱藏設定顯示已儲存內文。人物隱藏開啟時，名冊姓名／別名與聊天輸入框一樣只高亮，不寫進手動區間；同一顆按鈕可以逐處標記，或取消這一處自動標出的人名與個資。開始整理或送出時才把尚未取消的人名換成人物代號。
2. 「開始整理」只準備並保存本機資料，不檢查 AI 連線或送出請求，也不把日記顯示為使用者訊息。
3. 空聊天室顯示「語句潤飾／內容精簡／段落整理／引導補充」四張卡片及輸入框。點卡片直接送出完整需求，保留未送出的文字及隱藏區間；開始對話後改為「模型／整理日記」上方的單排膠囊快捷列，超出寬度可左右滑動。每次點擊追加一個需求，回覆後可接著選其他方向，最後一起整理；忙碌、編輯訊息或存在衝突時停用快捷。
4. 語句潤飾、內容精簡、段落整理用一兩句說明最需要改的地方或段落安排。段落整理遇到時間或地點不明時保留原有的不確定性，只有無法保留原意時才問一個問題，並先說出預設排法。引導補充只問一句與可見內容有關、幾個字就能回答的問題。略過問題直接生成時依原文整理，保留不確定性。使用者未更正就按「整理日記」時，生成採用這份修改說明；若使用者後續更正，則以最新更正為準。
5. 完整回覆後可繼續討論，或按「整理日記」生成全文。忙碌、編輯訊息、輸入框尚有未送出內容或目前分支沒有完整回覆時，停用生成。
6. 生成使用聊天日記相同的底部進度面板並提供停止；成功後直接進入「查看修改」，提供「返回聊天／手動編輯／確定修改」。按「返回聊天」會刪除這份未採用稿，保留需求對話，再次生成以原文及目前分支為基礎。

聊天室共用標題列、訊息、輸入區、模型選單、複製、編輯、重試及預覽元件；整理 controller 與儲存獨立。右上角只有請求預覽與刪除。刪除需確認，只清除本次整理資料。一般回覆的停止按鈕位於輸入區；不另開進度對話框。

### 提示詞與隱私

日記整理的請求包含共用固定規則 `organizationRulesPrompt`、該階段的固定輸出規則，以及有效的自訂或內建引導。需求對話使用 `organizationDiscussionRulesPrompt`，只說明改法。生成使用 `organizationDraftRulesPrompt`，回傳 `reply` 與 `body` 兩個字串欄位。遮蔽後的 `original` 隨 `diary_data` 放在系統提示詞，內文中的問題、指令和待辦只作為素材。

送出與預覽依當下設定與語系組裝。AI 設定可分別覆寫 `organizationConversationPrompt` 與 `organizationGenerationPrompt`，還原規則同[聊天日記](#預設提示詞與生成)。覆寫存在 `ai_settings.json.enc`，隨完整備份還原。

需求對話以尚未套用的語氣說明改法。按下整理後，可採用範圍內的改法，補充事實以原文或使用者確認為準。需求與代號保留規則衝突時，保留相關片段與順序，並說明限制。

只使用本篇內文與本次選定的聊天分支，不帶入原始聊天日記或其他日記。人名判定、代號分配與送出遮罩跟聊天日記共用 [`privacy_names.dart`](../../../lib/domain/ai/privacy_names.dart)。人物隱藏開啟時，可確定的人名換成 `{{PER_NN}}`，不需要先圈選；同一位人物的姓名與別名由 [`privacyTokenForPerson`](../../../lib/domain/shared/privacy_tokens.dart) 共用同一個代號，所以它會在原文重複出現，並另外依出現順序保留每次寫法。重名、手動選取與圖片仍用 `{{PRI_NN}}`。與姓名完全相同的手動選取改記成人物代號；選取若還包住其他文字，整段維持私密代號。整理稿必須保留這些代號的出現次數與先後順序，對照原文只留在本機。編號規則與聊天日記共用：至少兩位的大寫十六進位，超過 `FF` 接續 `100`。圖片引用不送出圖片、附件或引用網址。手動隱藏區間不會因開關重算。開始整理與之後送出讀取當時的人物隱藏開關；已保存的舊手動區間維持原樣，不自動改寫。

「完整 JSON」沿用[聊天日記的預覽格式](#預設提示詞與生成)，兩組請求各以 `diary_body` 顯示遮罩後的原始日記。原始日記另有可展開的卡片，送出時與系統提示詞組成 system prompt。聊天包含待送需求，生成沿用目前分支中的已送出內容。內容、標記、分支或模型改變時重建請求快照。隱藏設定頁不提供預覽。

### 候選稿與對比

候選稿只存在「查看修改」及套用階段。完整接收、JSON 解析、保護代號驗證及加密儲存成功後才顯示；生成失敗或停止不採用稿件。生成不新增聊天回合，`reply` 與候選一起加密保存，作為兩行修改說明並可展開全文，不寫入日記或下一次對話。說明若含任何保護代號，改用本機安全提示，合格的正文仍可採用。手動修改正文後清除舊說明；返回聊天會先清除候選、說明與請求快取，保存成功才切頁。直接關閉對比頁保留進度；說明對話框在真正進入背景或鎖定時關閉，背景畫面遮蔽整理內容。

手動編輯沿用共用的圓角對話框，提供取消與確定，只能更動保護區段以外的文字。保存失敗保留原候選稿，成功才更新對比；返回聊天也會清除手動修改後的候選稿。來源代號不得遺漏或換序，出現次數也必須相同。目前分支使用者實際送出的新增代號可納入，新增人物代號可重複，新增 S 代號至多一次；不能從 AI 回覆、其他分支或未送輸入擴張範圍。生成依實際請求驗證，手動修改、保存與套用再次驗證。

聊天畫面逐回合僅使用原文及該回合祖先需求中的對照，串流到達時即受此限制；其他分支及未來回合的代號保持原樣，不還原秘密。越界的完整回覆標為未完成，不供後續請求或生成使用。舊檔若有結構完整但範圍不符的候選，仍保留需求對話，候選內容不顯示也不能編輯、保存或套用，可離頁或返回聊天清除該候選，不搬移或推測修補。

兩種生成提示詞都以自然段落為主，必要時才用單層條列、編號或真正的待辦，不新增多層 Markdown 標題、粗斜體、表格或程式碼圍欄。聊天生成首行的 `# 標題` 供擷取日記標題，內文不另外使用標題語法；整理僅更新內文。

修改對比在本機先對齊行，再比較 Unicode 字素；整份共用計算額度，差異過大時改用整行增刪。舊行與新行分開，使用淡紅／淡綠底及行首 −／＋，實際變動的字加深底色。保留完整內容，不提供版本選單、圖例、行號或 Git 標頭。非空行保留固定內距與行高，未修改的空白行較矮；支援系統文字縮放。

對比與全文共用主題設定的分段切換元件，全文沿用唯讀日記閱讀排版。三顆操作按鈕同高且有邊框，窄畫面或大字體改為等寬直排。確定修改只更新內文，標題、日期、標籤及附件維持原值；返回檢視頁時同步控制器、目前日記與儲存基準，舊快取不得覆蓋結果，編輯中不覆蓋輸入。

### 暫存與恢復

整理保存來源、隱藏區間、目前分支、輸入及一份候選稿，讓離頁後可繼續。返回聊天會清除未採用的候選稿；執行中的請求不會自動重送。必要隱私對照或座標損壞時保留檔案並拒讀，不裁切或推測重建。

檔案路徑、JSON 必要與可選欄位、版本及恢復規則統一見[本機儲存](../資料/本機儲存.md#日記整理-json)。

### 生命週期與套用恢復

只開啟而未操作不保存；修改隱藏標記、輸入或開始整理後保存。一般返回先完成保存；離頁後請求繼續，重新進入接回同一工作。鎖定停止請求並清除整理 controller 的草稿與請求快照；程序終止後的處理同[訊息與分支](#訊息與分支)，由使用者自行重試。

套用在同一日記庫寫入序列內重新檢查來源；來源已變更或有未處理編輯草稿時，禁止覆蓋。衝突提示保留目前稿供查看，並提供「以最新日記重新整理」。套用前先保存 applying 狀態；若正式日記已寫入、清理前中斷，下次以目標內容辨識完成並清理；未寫入時回到對比頁。生成與手動修改都先儲存候選稿，成功才更新畫面。

完成、確認刪除整理或刪除原日記都清除整理目錄。刪除與鎖定使晚到回覆失效，晚到寫入不能重建已刪草稿。正式完成聊天不受整理清理影響。本機清理不代表服務商刪除已接收資料。
