# AI

手機直接連線使用者指定的服務，開發者不提供 AI 中繼伺服器。聊天日記與日記整理共用 AI 連線、聊天介面、模型選單、請求預覽及生成進度元件；正式聊天與整理暫存分開保存。人物隱藏是同一個開關，寫在設定檔頂層 `hide_people`。兩組提示詞覆寫有內容時才分別寫進 `chat_diary` 與 `diary_organization`。文字區間、人物區間與輸入快照在 [`private_text.dart`](../../../lib/domain/ai/private_text.dart)。

使用者資料如何傳送、保留與刪除的公開承諾見[隱私權政策](../../privacy-policy.md#ai-服務與聊天資料)；本文件只記錄實作與維護規則。

## 共用

### 訊息呈現

聊天室、日記整理與請求預覽共用 `AiMessageView` 的左右對齊、泡泡寬度、圓角、內距、配色、圖片排列與隱藏高亮。角色標籤、尚未送出狀態及聊天操作由各頁提供。使用者訊息及請求預覽使用純文字；聊天室與整理的 AI 回覆保留 Markdown，預覽顯示實際外送的原始語法及代號。

### 輸入人物名稱

聊天日記與日記整理的輸入框共用 `@`／`＠` 人物建議。依姓名及別名搜尋，選取後插入指定的日記稱呼，移除 `@` 且不自動加空白；仍是一般文字，送出時沿用人物隱藏設定。手動隱藏的文字區間會隨替換調整。

人物建議以 chip 列放在輸入框外側下方、鍵盤上方，不另加底條，與輸入框間隔 8px，可左右滑動，也支援上下方向鍵、Enter 選取及 Esc 關閉；中文組字期間不攔截確認鍵。名冊僅在查詢作用中訂閱，不額外啟動人物統計；已有統計才沿用排序。名冊為空或沒有符合項目時，可預填查詢文字開啟人物新增表單，儲存後回填有效的原查詢。忙碌時收起建議；背景、鎖定、切換對話或離頁時關閉本次人物表單並忽略過期回傳。已完成聊天沒有輸入區。

### 連線與模型

| 提供商 | 協定與圖片傳送 |
|------|------|
| OpenAI | Responses；圖片經 Files API 上傳後引用 |
| Claude | Messages；圖片經 Files API 上傳後引用 |
| Gemini | GenerateContent；圖片經 Files API 上傳後引用 |
| xAI | Chat Completions；圖片以內嵌 data URL 傳送 |
| Custom（多組具名連線） | Chat Completions、Responses、Claude Messages、Gemini GenerateContent 或 Ollama Chat；圖片使用所選協定的內嵌格式 |

供應商順序、官方模型、預設開關及思考強度由 [`ai_catalog.dart`](../../../lib/domain/ai/ai_catalog.dart) 管理，設定與請求欄位轉換在 [`ai_connection_settings.dart`](../../../lib/domain/ai/ai_connection_settings.dart)。

- 新供應商套用目錄預設；已看過的模型維持開關，未看過的新模型才套預設。移除舊官方模型後，若原本開著且沒有其他啟用模型，才啟用新預設；單純移除目錄項目不會重新啟用已關閉的現有模型，新增目錄項目仍依前述規則處理。沒有官方來源記錄的舊名稱保留為手動模型。
- 設定依序顯示說明、隱藏人物姓名、聊天日記、日記整理、模型、官方 API 及自訂連線。模型卡片分開顯示名稱、供應商與思考設定，以底色及開關辨識啟用狀態；手動模型的刪除 X 位於開關左側。主列表在開啟設定、加入模型或新增連線時重排，先列啟用模型，再依供應商、連線建立順序、目錄及手動加入順序排列，顯示前 10 筆；重複加入會啟用既有模型並重排，單獨切換開關或 Thinking 時維持位置。「更多」依供應商及自訂連線分區，區內依版本數字由大到小、再依名稱排列。變更按「儲存」才保存，取消則捨棄。
- Thinking 膠囊按鈕顯示目前思考強度，選單只列該模型支援的選項，固定模式不顯示按鈕。主列表與「更多」共用設定，窄畫面或大字級時控制項換行。`thinking_levels` 依模型保存偏離預設的選擇，連線測試、聊天與生成使用同一轉換規則；Ollama 轉成 `think` 布林值。
- OpenAI、Claude、Gemini、xAI 需有 API Key；Custom 有網址即可。沒有可選模型時顯示紅字，儲存後仍留在設定頁。各供應商的連線測試互相獨立。
- 聊天的浮動選單固定在模型按鈕上方，依內容決定寬度，最多 320 logical pixels，並受螢幕可用寬度限制；高度以按鈕上方可用空間為限，長名稱換行、項目過多時可捲動，目前模型以勾號標示。點外部、按 Esc、進入背景或鎖定會關閉選單，晚到的設定不會重新開啟。選單只列啟用且連得上的模型；目前正在用、但已關閉或清掉金鑰的模型留在最後。切換會更新本則聊天及下一則新聊天的預設，其他既有聊天不變。
- Custom 的 Base URL 可含 `/v1`、`/v1beta` 或 `/api`；原生協定補齊需要的前綴，已有版本路徑不重複加入。Chat Completions 須自行包含服務要求的前綴。Ollama 圖片能力透過 `/api/show` 查詢，不依模型名稱猜測。

API Key 只留在裝置安全儲存。每組 Custom 連線依穩定連線 ID 與正規化網址分開保存；同網址可使用不同 Key。換網址先清空欄位，再讀取該連線在新目的地的金鑰；清空後儲存即可刪除。確認刪除自訂連線並儲存後，會一併刪除該連線各目的地的 API Key；取消、改名或只換網址不會刪除。舊自訂連線保留原網址識別，升級不要求重新輸入 Key。服務、具名連線、模型、思考設定、網址、協定、Claude Workspace ID、自訂提示詞及人物隱藏寫在加密日記庫，會隨完整備份還原。儲存位置與備份邊界見[本機儲存](../資料/本機儲存.md)。

自訂區以可收合卡片管理多組連線，同時展開一組。名稱不可空白，使用中的名稱不可重複。聊天選項依連線 ID、目的地與模型區分，聊天標籤顯示「精簡網址／模型」，省略 http(s):// 並保留埠號與 API 路徑；相同標籤才在第二行補連線名稱。完整網址與名稱保留在提示文字及無障礙標籤，設定列表直接顯示連線名稱。相同網址或同名模型也不會合併。新增連線不切換有效的聊天預設；選擇聊天模型才更新下一篇使用的連線與模型。

刪除自訂連線先顯示全 App 共用的紅色刪除確認，外層儲存後直接移除設定，並刪除該連線各目的地的本機 API Key，不封存或提供恢復；取消外層設定不會刪除金鑰。舊版已封存的項目讀取時略去並回寫。既有聊天仍保留原連線快照，但之後的請求與遠端清理不再持有該金鑰；從原聊天開啟設定時，仍可為該快照重新輸入金鑰。被刪除草稿尚未儲存的 Key 變更不會寫入。移除全域預設後改選第一組可用連線；沒有可用連線時需完成設定。從聊天室開啟設定時，編輯其他連線不會將目前聊天換到全域預設；原目的地已異於保存設定時，保留原聊天快照，另提供該目的地的金鑰欄位。

連線測試送一則「Reply with OK.」的非串流請求，最多等待 45 秒。一般請求的標頭與串流／非串流本文都有五分鐘逾時，本文逾時會中止連線。錯誤不顯示服務商回應本文。

協定、Thinking、聊天模型及人物排序共用選單樣式；欄位選單與欄位等寬，聊天選單維持向上彈出。隱藏人物姓名獨立放在聊天日記與日記整理之前，說明置於開關下方。聊天的新訊息，以及整理裡尚未確認的預選，送出或開始整理時讀這個開關。兩個區塊都只用緊湊操作列放提示詞，日記整理不另加介紹。

### Thinking 參數的來源與限制

模型目錄人工指定每個官方模型的 Thinking profile、可選強度與預設值，再由 `thinkingRequestFields()` 轉成請求欄位。支援範圍應依該模型與 API 的官方文件維護，例如 [OpenAI reasoning effort](https://developers.openai.com/api/docs/models/gpt-6.1-terra)、[Claude Sonnet 5.5 thinking](https://platform.claude.com/docs/en/models/sonnet-5-5/whats-new-sonnet-5-5)、[xAI reasoning](https://docs.x.ai/developers/model-capabilities/text/reasoning) 及 [Ollama thinking](https://docs.ollama.com/capabilities/thinking)。App 的預設強度與四個介面選項是產品設定，不代表供應商的預設或全部支援值。

自訂連線新加入的模型預設不傳送 Thinking 參數；既有模型與重複加入保留原設定。手動模型可從 Thinking 選單開啟設定，沿用關閉／低／中／高，停用不支援的檔位並指定有效預設。格式只保留不傳送參數、沿用目前協定及手動 JSON。手動模式以目前協定對照作為初始欄位，既有自訂 JSON 則原樣載入；切換模式保留尚未套用的輸入。手動 JSON 直接併入請求，除了 Thinking 也可能改變輸出長度或其他行為並增加服務費用，請依該模型官方文件設定。沒有覆寫時仍使用既有協定規則，不自動查詢或確認模型能力。

手動 JSON 模式直接顯示完整的進階對照，不提供收合；每個啟用檔位可編輯 JSON object，保留字串、數字、布林、null、陣列與巢狀物件；`{}` 表示該檔不傳參數。不傳送模式不提供強度選項，但仍可開啟設定。Ollama 的協定預設以布林值控制 Thinking；需要 low／medium／high 等模型專用格式時，使用手動 JSON 設定。

`AiModelThinkingOverride` 深度凍結 JSON，覆寫保存在各連線的 `thinking_overrides`，選取強度仍用 `thinking_levels`。進階請求覆寫取代協定產生的 Thinking 欄位，再遞迴合併到請求；禁止覆寫 model、messages、input、instructions、contents、system、systemInstruction、stream 與 store。其餘欄位（例如 max_tokens）會一併送出，可能改變輸出或費用。無效輸入留在欄位並阻止套用，後端拒絕時不自動改參數重試。

設定視窗的「套用」只改外層草稿，外層「儲存」才保存；取消不保存。連線測試、聊天與生成使用相同解析規則。有效參數、連線或 Key 改變時重建客戶端；JSON 鍵順序改變不重建。舊訊息快照保留當時的連線與該模型對照。

自動測試驗證目錄、參數映射及模擬請求，不會逐一呼叫真實模型；通過測試不等於已取得每個模型的線上相容性驗證。實際支援值仍需對照官方文件，並視需要以合成內容另外驗收。

### 傳輸與協定

Custom 的 HTTPS 可用指定主機；HTTP 只允許 loopback、IPv4 私有網段及 IPv6 ULA，拒絕主機名稱、link-local 與公網 HTTP。送憑證前由 `validateAiEndpoint` 驗證，不跟隨重新導向、不略過 TLS 驗證。Android 設定見[權限與資料揭露](../google/Android-權限與資料揭露.md)。

Responses 送出 `store: false`，不代表零留存；Custom 的資料使用與留存由該服務決定。API 參考：[OpenAI 圖片](https://developers.openai.com/api/docs/guides/images-vision)、[Responses](https://developers.openai.com/api/reference/resources/responses/methods/create)、[Claude Messages](https://platform.claude.com/docs/en/api/messages/create)、[Gemini](https://ai.google.dev/api/models)、[Ollama](https://docs.ollama.com/api)。

## 聊天日記

首頁按「新增日記」後，每次選擇直接寫日記或聊天日記；手機使用底部卡片面板，600px 以上使用最大 480px 的中央視窗。選擇前不建立日記或聊天草稿，取消會保留首頁搜尋與篩選；鎖定、切換日記庫或進入背景時關閉選擇器。聊天仍沿用既有 AI 連線檢查與設定流程。未完成聊天列在首頁；正式儲存後可從日記檢視頁開啟完成聊天。

### 預設提示詞與生成

兩份預設是 `chatDiaryConversationDefaultSystemPrompt`、`chatDiaryGenerationDefaultSystemPrompt`，唯一內容來源為 `lib/l10n/*.arb`。繁中預設繁體中文與台灣用語，英文預設英文；只有使用者明確指定適用範圍才切換。自訂內容不隨 App 語言改寫，還原只清除該用途的覆寫。設定預覽及實際請求共用 `resolveChatDiaryPrompt`。預設內文以自然段落為主，必要時才使用單層列表或真正的待辦，不堆疊多層 Markdown 標題、粗斜體、表格或圍欄；首行 `# 標題` 僅用來擷取獨立的日記標題。自訂提示詞維持原值。

聊天先回應當下的重點，像朋友自然接話；不必每輪提問，每輪最多一個問題。不為了蒐集日記素材而盤問，也不宣稱已儲存、建立待辦或設定提醒。生成會把目前分支完整可用對話序列化成帶有 user／assistant 角色的資料。assistant 提供語境，用來理解短回答、更正、構想與話題關係；其推測、評論與建議不寫成使用者的經歷或決定。

| 使用者意圖 | 生成方式 |
|------|------|
| 經歷或感受 | 第一人稱自然段落，保留用字、情緒與不確定性 |
| 構想、規劃，或以提問提出的需求 | 連貫的想法紀錄；必要時用簡短小標題。未定事項保持未定 |
| 明確要記得做、可辨識完成的事項 | `- [ ]` 待辦 |
| 明確追蹤的待辦已完成，或要求標示完成 | `- [x]`；一般已發生的事仍用敘述 |
| 願望、習慣目標、功能需求或討論中的方案 | 一般文字；明確要求列為待辦才轉換 |
| 經歷、構想與待辦混合 | 依內容混合段落、小標題與清單，不套固定作文或會議紀錄 |

生成閱讀整段對話，不因最後一輪只是補充就丟掉前文，並遵守最新更正、長度與排除要求。簡短的確認、否定或修改要保留。AI 單方面提出的選項，以及沒有反駁的猜測，不寫成使用者的決定或未決問題；使用者明確想留下的知識或討論成果可以記。圖片只採用清楚可見且相關的資訊，不推定身分或拍攝情境；人物與私密代號逐字保留，不輸出對照表或附件路徑。模型只輸出一級標題及 Markdown 成品，無可記內容時輸出空字串。

`generate()` 回傳 `ChatDiaryGenerationResult`：成功提交為 `generated`，正常結束但內容空白為 `empty`，失敗、取消或無法開始為 `notGenerated`。空內容留在聊天室顯示提示，保留原草稿、附件、來源與快照；不建立私密補記或交接編輯器。傳輸錯誤維持原錯誤處理。

聊天室儲存新設定會停止舊請求並保留進度。API Key、連線或有效思考強度改變時，下次請求重新建立客戶端。舊回覆保存當時連線與有效提示詞，生成另存其快照。

### 訊息與分支

- 固定歡迎訊息只在本機顯示，不進入請求或日記事實，續聊沿用原開場。
- `parentId` 建立訊息樹，`selectedChildren` 保存版本選取，`activeMessages` 為目前路徑。編輯重送與重新回覆新增版本；切換版本不連線。沒有父訊息、錯誤或該則連線時，不寫 `parent_id`、`error_code`、`connection`。尚未生成或編輯時，不寫 `generation_connection`、`generated_entry_id`、`generated_from_message_id`、`generated_draft_signature`、`editing_message_id`、`edit_backup`。`edit_backup` 沒有圖片時不寫 `image_ids`。
- 編輯以 `editBackup` 保存原輸入、私密區間及附件，取消或送出後還原。圖片引用涵蓋全部分支、輸入與編輯備份。
- 請求預覽可切換「聊天／生成日記」，共用整理預覽的分段切換、提示詞卡片及最高 90% 寬度。聊天包含目前上下文與待送內容，編輯時只取目標訊息以前；生成只包含已送出的目前分支，預覽以同一組聊天氣泡及各訊息的圖片呈現，實際送出仍打包為對話 JSON，不帶待送文字或圖片。兩者排除失敗或中斷的 AI 回覆，使用各自的提示詞。
- 訊息列表延遲建立，接近底部才跟隨串流；讀舊內容時保留位置。等待動畫尊重減少動態效果設定。
- 請求期間停用功能操作，仍可捲動與返回。失敗及中斷回覆留在原位供重試；完成聊天唯讀，仍可切換版本。
- 離開聊天室或切換 App 時，進行中的回覆與生成繼續收到結束並保存；重新進入接回同一請求。請求與最終保存完成後，無畫面使用的 controller 才釋放。背景仍遮蔽畫面並關閉圖片、預覽與選單；鎖定或工作階段失效時停止請求、清除聊天與輸入，保留加密進度。
- 生成狀態由聊天室與首頁草稿卡共用，依實際事件顯示準備、等待模型、撰寫及儲存階段，不估算百分比。狀態卡只提供停止生成，使用者仍可按返回離頁或切換 App。首頁只顯示狀態標籤。失敗原因與重新生成、草稿狀態與查看草稿，都在聊天室訊息列表頂端的同一條提示，一次只出現一種。
- 聊天回覆與日記生成都只送一次。連線中斷或程序被系統終止後不自動重送；重新開啟沿用已保存的對話與草稿，工作狀態不跨程序保存。生成不使用前景服務或系統通知。鎖定與晚到結果見[解鎖與會話](../安全/解鎖與會話.md)。
- 生成成功先提交草稿，真正開啟編輯器才交接。只有持續留在原聊天室且未切到背景時才自動開啟；其餘情況由首頁或聊天室查看，不強制導頁。
- 連點只啟動一次流程。等待保存時若已離頁則不交接編輯器，也不阻擋後續聊天。點擊首頁草稿卡進入聊天室後才重試或查看草稿。
- 首次保存及請求結束後更新首頁草稿；刪除聊天先取消作業並排空待寫入，再刪除，晚到內容不能重建草稿。

### 文字隱私與私密補記

`ChatDiaryPrivacyProcessor` 只替換使用者反白區間，不連帶替換其他相同原文。每次依原文及反白區間重算外送文字。人物只在該則送出時比對名冊，命中區間記在訊息上；之後增刪改人物或別名，都不再改已送出的訊息。有效提示詞仍會替換目前分支已標記的原文。

人物 `P` 與私密片段 `S` 各自遞增：`⟦P01⟧`、`⟦S01⟧` 等至少兩位的大寫十六進位代號，超過 `FF` 接續 `100`，不循環重用。同一人物姓名與別名由 [`privacyTokenForPerson`](../../../lib/domain/shared/privacy_tokens.dart) 共用代號，還原成第一次出現的寫法；同一私密原文沿用代號。原文、區間及對照表只在本機加密保存。已送出的使用者訊息只用送出當下記下的區間，以同一層隱藏底色標出姓名。輸入框與送出預覽不標人物，預覽仍顯示代號。

聊天訊息與送出預覽的隱藏底色共用 `PrivateText`／`PrivateText.rich`，依文字實際排版的行高繪製，不替高亮文字更換字型。中文、英文與隱私代號在同一行內使用相同高度；跨行、字級與主題變更沿用相同規則，文字仍可選取及複製。Markdown 解析時將來源區間映射到各段可見文字，移除的語法與新增的標點不標記；隱藏區間的行內程式碼讓出底色，保留原字型。

聊天的 AI 回覆以 `restoredPrivateRanges` 比對保存的外送文字、已還原文字及代號對照表，只高亮實際由 `P`／`S` 代號還原的內容，不重新搜尋人物名冊或同名原文。未知、不完整及仍以代號顯示的部分不標記；整則文字無法完整對齊時不猜測區間。區間於呈現時計算，不另存欄位，串流、重載、版本切換及完成聊天使用相同規則。整理回覆沿用 `organizationVisibleText` 的還原區間。這些呈現不會改寫保存原文或將還原文字重新送給模型。

生成後在手機還原目前分支的代號。已送出但未被模型引用的私密片段仍會自動附加到「私密補記」；這是 App 的本機保存規則，AI 的素材篩選或排除要求無法阻止此追加。使用者可在編輯器刪除不想保留的補記。還原後原文不自動回送模型，其他分支不補入。

App 不另外辨識電話、地址或一般敏感詞，也不會隱藏圖片上的內容。供應商資料政策見[隱私權政策](../../privacy-policy.md#ai-服務與聊天資料)。

### 圖片與清理

聊天保存原圖，一般編輯器的新圖片依個人化設定壓縮；生成交接不重選、不重壓縮。傳送副本保留 JPEG／PNG／WebP／GIF 的原尺寸與壓縮像素、方向、色彩及動畫必要資料，移除私密與未知附屬區塊，包含動畫 WebP 影格。其他可解碼格式轉原尺寸 PNG；大型位元組清理在背景 isolate 執行，不另設張數或容量上限。

使用 Files API 的提供商上傳後先保存遠端清理紀錄才發布快取。記錄失敗會嘗試刪除遠端檔，重試重新上傳。紀錄依連線快照分檔，不含 API Key；完成或刪除聊天後清理，失敗於之後進入 AI 功能時重試，未完成聊天的遠端圖片保留。重試只移除本次成功刪除的參照，不覆寫等待期間新增的紀錄。

移除引用及取消附圖時，晚到寫入仍須清除本機圖片與 `.previous`、`.tmp`。

### 草稿交接與完成聊天

一段聊天共用一份生成草稿。一級標題取為標題，其餘保留為內文；自訂輸出沒有一級標題時全作內文。`generatedFromMessageId` 記錄來源版本，切換分支或新增內容會提示草稿可能過期；人工編輯以內容指紋辨識，取代前先確認。

附件逐張解密暫存，依本機 ID 去重並保持首次送出順序。發布前再次檢查操作有效性，取消或失敗只清本次暫存；提交點一起更新來源、連線、提示詞與指紋，提交後離頁仍完成保存。

正式日記儲存成功後才保存完成聊天、刪除聊天草稿與解密預覽。中斷收尾在下次讀取草稿清單時補完，重複收尾可辨識已完成聊天。編輯器保存與 checkbox 持久化見[日記編輯器](日記編輯器.md)。

完成聊天只沿用正式附件，未收錄或已移除圖片顯示「圖片已刪除」。完成聊天沒有輸入區或「開啟日記」按鈕，按返回回到日記，重新進入時重讀附件。AI 與使用者訊息使用相同圓角與內距、不同底色；聊天與送出預覽的文字皆沿用一般日記內容的字型、字級與行高。送出預覽保留原始文字與私密代號供檢查；生成按鈕位於模型選擇右側，窄版依序為上方靠右的生成、下方靠左的模型。刪聊天不刪日記；刪日記會清相鄰聊天及恢復檔。改日期與修復搬移一起處理聊天，衝突保留來源並回報。備份流程見[備份與還原](備份與還原.md)，加密格式見[加密格式](../安全/加密格式.md)。

## 日記整理

日記檢視頁的 AI 選單提供「檢視聊天日記」與「日記整理」。沒有保留聊天時，檢視項目停用；有整理草稿時改顯示「繼續整理」。手機使用底部面板，600px 以上使用中央對話框。

### 操作流程

1. 進入日記整理時，若目前連線缺少模型、必要網址或 API Key，自動開啟 AI 設定。設定完成後更新本次整理連線；取消後留在整理畫面，同次進入不重複彈出，也不送出 AI 請求。隱藏設定顯示已儲存內文，依 AI 人物隱藏設定及名冊姓名／別名預選區間。預選與手動標記共用可編輯區間，皆能逐處取消並持續高亮；隱藏按鈕位於「開始整理」同列左側。
2. 「開始整理」只準備並保存本機資料，不檢查 AI 連線或送出請求，也不把日記顯示為使用者訊息。
3. 空聊天室顯示「語句潤飾／內容精簡／段落整理／引導補充」四張卡片及輸入框。點卡片直接送出完整需求，保留未送出的文字及隱藏區間；開始對話後改為「模型／整理日記」上方的單排膠囊快捷列，超出寬度可左右滑動。每次點擊追加一個需求，回覆後可接著選其他方向，最後一起整理；忙碌、編輯訊息或存在衝突時停用快捷。
4. 語句潤飾、內容精簡、段落整理直接說明整理時會改的具體文字，不再詢問要不要改或希望怎麼調。段落整理只有在兩種理解會寫成不同事實時才問一個問題，並先說出預設排法。引導補充每次只問一個與可見內容有關的具體問題，不追問隱藏內容、人物身分，也不先問想補充哪個方向。使用者未更正就按「整理日記」時，生成採用這份修改說明；若使用者後續更正，則以最新更正為準。
5. 完整回覆後可繼續討論，或按「整理日記」生成全文。忙碌、編輯訊息、輸入框尚有未送出內容或目前分支沒有完整回覆時，停用生成。
6. 生成使用聊天日記相同的底部進度面板並提供停止；成功後直接進入「查看修改」，提供「返回聊天／手動編輯／確定修改」。按「返回聊天」會刪除這份未採用稿，保留需求對話，再次生成以原文及目前分支為基礎。

聊天室共用標題列、訊息、輸入區、模型選單、複製、編輯、重試及預覽元件；整理 controller 與儲存獨立。右上角只有請求預覽與刪除。刪除需確認，只清除本次整理資料。一般回覆的停止按鈕位於輸入區；不另開進度對話框。

### 提示詞與隱私

需求對話只討論整理方式，不輸出整篇修改稿。生成提示詞要求只輸出含 `reply` 與 `body` 的 JSON。兩者都使用既有 AI client 的 system prompt 通道，遮罩後的原始內文 `original` 放入 `diary_data` 資料區塊；日記中的問題、指令或任務清單不當作當前操作指令。

兩份預設是 `organizationConversationPrompt`、`organizationGenerationPrompt`，唯一內容來源為 `lib/l10n/*.arb`。AI 設定的日記整理區塊可各自覆寫；自訂內容不隨 App 語言改寫，還原只清除該用途的覆寫。送出、生成與預覽當下依最新設定與 App 語系解析，不改寫已送出的對話。覆寫與聊天日記提示詞同在 `ai_settings.json.enc`，隨完整備份還原。

只使用本篇內文與本次選定的聊天分支，不帶入原始聊天日記或其他日記。人物區間以 `⟦P01⟧` 這類代號替換。同一位人物的姓名與別名由 [`privacyTokenForPerson`](../../../lib/domain/shared/privacy_tokens.dart) 共用同一個代號，所以它會在原文重複出現，並另外依出現順序保留每次寫法。其他選取與圖片仍依位置各用一個 `⟦S01⟧` 代號，文字相同也不共用。整理稿必須保留這些代號的出現次數與先後順序，對照原文只留在本機。編號規則與聊天日記共用：至少兩位的大寫十六進位，超過 `FF` 接續 `100`。圖片引用不送出圖片、附件或引用網址。尚未改過隱藏區間時，從本頁儲存 AI 設定或按下開始整理，會依最新人物隱藏開關重算預選。已改過或已保存的區間（含全部取消）維持不變，重新進入與送出時也不重套；來源衝突後重新整理才讀取最新設定並重建預選。

聊天室預覽可切換「聊天／整理日記」：聊天包含待送訊息，整理只含原始內文及已送出的目前分支。預覽與送出共用遮罩後的請求快照，內容、標記、分支或模型改變時重建，避免把本機還原的私密原文送回 AI。系統提示詞與原始日記內容分卡顯示，資料區塊仍合併於實際 system prompt 中；對話框沿用共用寬度，最高為畫面 90%。隱藏設定頁不提供預覽。

### 候選稿與對比

候選稿只存在「查看修改」及套用階段。完整接收、JSON 解析、保護代號驗證及加密儲存成功後才顯示；生成失敗或停止不採用稿件。生成不新增聊天回合，`reply` 不另存成訊息。返回聊天會先清除加密暫存中的候選稿與請求快取，保存成功才切頁；失敗仍留在對比頁並保留候選稿。直接關閉對比頁則保留進度，重新開啟可繼續檢視。

手動編輯沿用共用的圓角對話框與 90% 寬度，提供取消與確定，只能更動保護區段以外的文字。保存失敗保留原候選稿，成功才更新對比；返回聊天也會清除手動修改後的候選稿。來源代號不得遺漏或換序，出現次數也必須相同；人物代號可以重複，其他代號不得重複。未知代號也拒絕採用。

兩種生成提示詞都以自然段落為主，必要時才用單層條列、編號或真正的待辦，不新增多層 Markdown 標題、粗斜體、表格或程式碼圍欄。聊天生成首行的 `# 標題` 供擷取日記標題，內文不另外使用標題語法；整理僅更新內文。

修改對比在本機先對齊行，再比較 Unicode 字素；整份共用計算額度，差異過大時改用整行增刪。舊行與新行分開，使用淡紅／淡綠底及行首 −／＋，實際變動的字加深底色。保留完整內容，不提供版本選單、圖例、行號或 Git 標頭。非空行上下內距 2px、行高 1.4、字級上限 16px，未修改空白行高 8px；支援系統文字縮放。

對比與全文共用主題設定的分段切換元件，全文沿用唯讀日記閱讀排版。三顆操作按鈕同高且有邊框，窄畫面或大字體改為等寬直排。確定修改只更新內文，標題、日期、標籤及附件維持原值；返回檢視頁時同步控制器、目前日記與儲存基準，舊快取不得覆蓋結果，編輯中不覆蓋輸入。

### 第一版暫存格式

路由 `/diary-organization/:entryId` 與檔案位置分開。同一日記庫與日記共用工作；草稿位於 `vault/diary_organization_drafts/{entryId}/session.json.enc`，使用 LDJ2 與可恢復寫入，不納入完整備份或匯出。格式由 [`DataVersions.diaryOrganization`](../../../lib/shared/data_versions.dart) 管理，目前維持第一版。既有對照表的長代號在讀取時改用短代號，來源代號內文、聊天及目前稿一併更新引用；未送出文字與隱藏區間保持原值，不另外升格式版本。`person_tokens` 與 `token_surfaces` 是第一版的可選欄位：前者記錄人物對應的 P 代號，後者只在同一個代號隱藏了不同寫法時，依出現順序保存每次原文。舊草稿沒有這兩個欄位時，讀取會依目前人物區間合併代號。

| 欄位 | 用途 |
|------|------|
| `version`、`source` | 格式版本與來源日記快照，供對比、衝突檢查及套用恢復 |
| `connection` | 本次使用的連線與模型快照，不含 API Key |
| `stage` | `privacy`、`chat`、`review`、`applying` 或 `applied` |
| `ranges`、`protected_source`、`originals` | 原文隱藏區間、穩定代號內文與本機對照表，保留使用者取消預選的結果。可選的 `person_tokens`、`token_surfaces` 讓同一人物共用代號，並在姓名與別名不同時逐次還原 |
| `turns`、`root_turn`、`selected_children` | 使用者需求與 AI 回覆、重試分支及選定路徑；未完成回覆標為 interrupted。使用者訊息若隱藏了人物代號的另一種寫法，該則另存 `surfaces` |
| `organized_body` | 檢視中的單一候選稿，尚未生成或返回聊天後為 null；不保存稿件歷史 |
| `generation_interrupted` | 生成前保存為 true，完整驗證與新稿寫入時一起改回 false；重開後只提示重試 |
| `composer`、`composer_ranges`、`editing_turn`、`composer_backup` | 未送出文字、隱藏區間、編輯目標與編輯前輸入，支援取消編輯及續作。沒有圖片時 `composer_backup` 不寫 `image_ids` |

來源原文與代號對照都在加密檔內；來源快照保留比較基準，穩定代號則避免多輪對話錯配。執行中的請求、請求快照快取、錯誤、busy 狀態及 API Key 不序列化。詳細路徑與備份邊界見[本機儲存](../資料/本機儲存.md)。

### 生命週期與套用恢復

只開啟而未操作不保存；修改隱藏標記、輸入或開始整理後保存。一般返回先完成保存；離頁後請求繼續，重新進入接回同一工作。鎖定停止請求並清除整理 controller 的草稿與請求快照；程序終止後也不自動重送，使用者自行重試。

套用在同一日記庫寫入序列內重新檢查來源；來源已變更或有未處理編輯草稿時，禁止覆蓋。衝突提示保留目前稿供查看，並提供「以最新日記重新整理」。套用前先保存 applying 狀態；若正式日記已寫入、清理前中斷，下次以目標內容辨識完成並清理；未寫入時回到對比頁。生成與手動修改都先儲存候選稿，成功才更新畫面。

完成、確認刪除整理或刪除原日記都清除整理目錄。刪除與鎖定使晚到回覆失效，晚到寫入不能重建已刪草稿。正式完成聊天不受整理清理影響。本機清理不代表服務商刪除已接收資料。
