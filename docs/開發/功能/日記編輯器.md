# 日記編輯器

一般新日記直接進編輯模式，既有日記預設進檢視模式。`EditorFlowController` 協調草稿、附件與正式儲存；Markdown 是內文的單一資料來源。

## 進入、離開與正式儲存

| 情境 | 行為 |
|------|------|
| 新建日記 | 使用 `__new__` 草稿，同時保留一份一般新日記草稿 |
| 既有日記 | 草稿 key 使用 `entryId`；有草稿時顯示未儲存標記 |
| 聊天生成日記 | 使用 `chat_diary_<id>` 草稿，直接還原並進編輯模式 |
| 手動修復 | 使用 salvage 草稿，直接還原 |
| 編輯中關閉 | 先完成排隊草稿保存；有修改時確認是否放棄，確認後刪除草稿 |
| 無修改時關閉 | 清除草稿；新頁離開，既有日記回檢視模式 |
| 正式儲存 | 寫入日記及附件、同步索引、刪除草稿並刷新查詢 |

一般草稿重開時詢問是否還原，拒絕即刪除。空白新日記不建立草稿。聊天生成與 salvage 是使用者剛產生的內容，直接套用；聊天儲存成功後才完成聊天交接，見[AI 聊天日記](AI-聊天日記.md)。

## 欄位規則

- 標題可空，標題或內文至少一項非空才能儲存。
- 日期使用 `DateOnly` 的 `YYYY-MM-DD`，時間使用 24 小時制。修改既有日期／時分時保留秒、毫秒及微秒；新日記取當下的秒以下時間。
- 標籤以逗號分隔、去除前後空白、折疊連續空白並依正規化文字去重，保留首次顯示形式。標籤順序參與 dirty 比對。
- 純文字儲存前移除前後空白；任務清單正規化時保留編輯所需的尾端文字行與結尾換行。

## 任務清單與預覽

內文含 `^\s*-\s*\[([ xX])\]` 任務行時切為混合區塊模式，可編輯、勾選及排序；刪除最後一項後回到純文字模式。游標中間插入任務會保留後續文字，不額外插入空白段落。區塊盡量保留 line ID，重組後仍是同一份 Markdown。

預覽使用 [`EditorMarkdownPreview`](../../../lib/presentation/editor/widgets/editor_markdown_preview.dart)。已儲存日記的預覽勾選會先樂觀更新內文，再正式儲存並同步索引，不只改草稿。

## 加密草稿

欄位或附件變更時排程保存；進入 `hidden`／`paused` 及關頁前立即嘗試保存。草稿不加入搜尋索引、統計或完整備份。

| 路徑 | 內容 |
|------|------|
| `drafts/{draftKey}/draft.json.enc` | 一般草稿 |
| `drafts/{draftKey}/pending/*.enc` | 一般草稿附件 |
| `vault/chat_diary_drafts/<chatId>/editor/draft.json.enc` | 聊天生成草稿 |
| `vault/chat_diary_drafts/<chatId>/editor/pending/*.enc` | 聊天生成附件 |

路徑由 [`VaultPathStrategy`](../../../lib/infrastructure/storage/vault_path_strategy.dart) 計算；[`EditorDraftStore`](../../../lib/infrastructure/storage/editor_draft_store.dart) 用 LDJ2 保存標題、日期時間、標籤、正文、附件順序與 pending 參照、provisional entry ID、建立／更新時間，以及 salvage 來源。

草稿寫入使用可恢復的檔案替換，發布後清除未引用 pending 檔及其解密預覽。生成流程可在發布前取消；原草稿與附件保留。金鑰與 vault ID 必須符合目前 session。

## 附件

圖片共用系統挑選器，Android 會接回中斷結果，先嘗試多選，失敗再退回單張。一般編輯器依[個人化設定](個人化設定.md#圖片品質)壓縮新圖片；GIF 保留原格式。聊天交接使用原圖，不重壓縮。

一般檔案透過系統選檔取得，直接加密至 pending。外部檔案材料化與授權釋放見[備份與還原](備份與還原.md#外部選檔與-materialize)。UI 不直接讀 `.enc`，預覽會解密至 `Directory.systemTemp/quill_diary_draft_preview/`。

既有與 pending 圖片可一起排序、移除。正式儲存時將附件順序與 pending 資料交給 `VaultRepository.saveEntry()`；成功後刪除該草稿資料夾。共用圖片檢視支援切圖、縮放與下載。

## 開發入口與狀態一致性

| 入口 | 責任 |
|------|------|
| [`editor_page.dart`](../../../lib/presentation/editor/pages/editor_page.dart) | 頁面模式、欄位 controller、生命週期及對話框整合 |
| [`editor_flow_controller.dart`](../../../lib/application/editor/editor_flow_controller.dart) | 草稿還原、附件 staging、dirty 狀態與正式儲存協調 |
| [`editor_actions.dart`](../../../lib/application/editor/editor_actions.dart) | 正式日記動作、聊天完成交接與查詢刷新 |
| [`editor_draft_models.dart`](../../../lib/application/editor/editor_draft_models.dart) | 草稿與 pending 附件紀錄；記錄相對路徑，不依賴裝置絕對位置 |

進入編輯時建立 dirty 比對基準，欄位、正規化正文、標籤順序與附件順序都須反映在草稿與正式儲存。返回確認前先完成排隊寫入，不能讓較晚完成的舊草稿覆蓋已還原或已儲存的新狀態。列表的未儲存標記由 `editorDraftKeysProvider` 取得；聊天生成草稿由聊天入口接手，不當作另一份一般 `__new__` 草稿。

草稿、pending 附件與解密預覽有不同生命週期：移除附件後，下一次草稿提交清理失去引用的 pending 與其預覽；正式儲存成功後清整份草稿；鎖定只保留加密草稿並清除明文預覽。失敗時不可先刪草稿，再要求使用者重新選檔。

### 需要保留的回歸邊界

- 還原一般草稿與直接還原聊天／salvage 草稿須各走正確入口，取消還原不留下 pending。
- 游標中間插入任務、刪除最後任務及區塊排序不能丟失後續文字或多生空白段落。
- 預覽勾選須走正式儲存與索引更新；編輯中的文字輸入只保存草稿。
- 已有圖片與 pending 圖片一起排序後，重新開頁、正式儲存與附件預覽仍使用相同順序。
- 背景、鎖定及關頁發生在寫入期間時，保留加密內容，清除解密預覽，阻止過期操作回寫。

流程測試位於 [`test/application/editor/`](../../../test/application/editor/)，UI 整合位於 [`test/presentation/editor/`](../../../test/presentation/editor/)；案例依[測試手則](../../../test/test-handbook.md)放在適當層，不必在每層重複同一規則。

## Session 與刪除

鎖定時先嘗試保存編輯內容，再清除解密附件預覽與已開啟資源。重新解鎖後依草稿狀態還原，保留先前正在編輯的上下文。

刪除日記同時刪除正式附件及相鄰聊天 JSON／恢復檔。日記改日期時一起搬移聊天，來源只在正式提交成功後清除。維護流程見[日記庫檢查與修復](日記庫檢查與修復.md)。
