# 日記編輯器

一般新日記直接進編輯模式，既有日記預設進檢視模式。`EditorFlowController` 協調草稿、附件與正式儲存；Markdown 是內文的單一資料來源。

## 進入、離開與正式儲存

| 情境 | 行為 |
|------|------|
| 新建日記 | 使用固定的 `__new__` 草稿 key，草稿保存在 App 資料的 `drafts/` 下，不進入日記庫 |
| 既有日記 | 草稿 key 使用 `entryId`；有草稿時顯示未儲存標記 |
| 聊天生成日記 | 使用 `chat_diary_<id>` 草稿，直接還原並進編輯模式 |
| 手動修復 | 使用 salvage 草稿，直接還原 |
| 編輯中關閉 | 先完成待寫草稿。寫入失敗時保留編輯畫面，可重試或另外確認捨棄草稿 |
| 無修改時關閉 | 清除草稿；新頁離開，既有日記回檢視模式 |
| 正式儲存 | 寫入日記及附件、同步索引、刪除草稿並刷新查詢 |

一般草稿重開時詢問是否還原，拒絕即刪除。空白新日記不建立草稿。聊天生成與 salvage 是使用者剛產生的內容，直接套用；聊天儲存成功後才完成聊天交接，見[AI](AI.md#草稿交接與完成聊天)。

檢視模式的編輯按鈕左側固定顯示 `AI` 圖示按鈕，開啟選單，提供「查看保留的對話」與「日記整理」；有整理草稿時後者改為「繼續整理」。沒有完成聊天時檢視項目停用，不建立對話或傳送日記內容。選單與後續流程見[AI](AI.md#日記整理)。

## 欄位規則

- 標題可空，標題或內文至少一項非空才能儲存。
- 日期儲存使用 `DateOnly` 的 `YYYY-MM-DD`；檢視與編輯工具列顯示 `YYYY/MM/DD HH:mm · 星期`，英文星期沿用縮寫。時間使用 24 小時制。修改既有日期／時分時保留秒、毫秒及微秒；新日記取當下的秒以下時間。
- 標籤以逗號分隔、去除前後空白、折疊連續空白並依正規化文字去重，保留首次顯示形式。標籤順序參與 dirty 比對。
- 純文字儲存前移除前後空白；任務清單正規化時保留編輯所需的尾端文字行與結尾換行。

## 任務清單與預覽

任務行依 [`diary_markdown.dart`](../../../lib/domain/diary/diary_markdown.dart) 的共用規則判斷，含 `- [ ]`、`- [x]` 或 `- [X]` 時切為混合區塊模式，可編輯、勾選及排序；刪除最後一項後回到純文字模式。游標中間插入任務會保留後續文字，不額外插入空白段落。區塊盡量保留 line ID，重組後仍是同一份 Markdown。

預覽使用 [`EditorMarkdownPreview`](../../../lib/presentation/editor/widgets/editor_markdown_preview.dart)。已儲存日記的預覽勾選會先樂觀更新內文，再正式儲存並同步索引，不只改草稿。

## 加密草稿

欄位或附件變更時，`EditorFlowSession` 依序寫入快照並合併待寫修改。比對時優先使用待寫或寫入中的版本，空閒時才使用最後落盤版本。離頁或進入背景時等待目前寫入，並對仍待寫的最新版最多重試一次。

草稿路徑、保護方式與備份邊界集中於[本機儲存](../資料/本機儲存.md#編輯草稿內部路徑)。[`EditorDraftStore`](../../../lib/infrastructure/storage/editor_draft_store.dart) 用 LDJ2 保存標題、日期時間、標籤、正文、附件順序與 pending 參照、provisional entry ID、建立／更新時間，以及 salvage 來源。

草稿使用可恢復的檔案替換，發布後清除未引用的 pending 附件。將新日記清空至初始狀態時移除草稿。鎖定時只等待有限時間，未落盤的最新版可在本程序解鎖同一日記庫與金鑰世代後重試。程序結束後可接回最後一次成功落盤的草稿。

## 附件

圖片共用系統挑選器，Android 會接回中斷結果，先嘗試多選，失敗再退回單張。一般編輯器依[個人化設定](個人化設定.md#圖片品質)壓縮新圖片；GIF 保留原格式。聊天交接使用原圖，不重壓縮。

一般檔案透過系統選檔，檢查格式後原樣加密至 pending。圖片按需解密至記憶體，壓縮結果也直接留在記憶體，一般附件到正式儲存時才解密至記憶體。大檔的加解密與雜湊在背景執行。

手動加入時一般檔案每個最多 25 MB，圖片每張最多 10 MB，兩個選取入口都適用。選圖在壓縮前檢查整批，任一張超過上限就拒絕該批。

既有與 pending 圖片可一起排序、移除。正式儲存時將附件順序與 pending 資料交給 `VaultRepository.saveEntry()`；成功後刪除該草稿資料夾。共用圖片檢視支援切圖、縮放與下載。

## 開發入口與狀態一致性

元件擁有權與程式入口見[模組參考](../架構/模組參考.md)。

列表的未儲存標記由 `editorDraftKeysProvider` 取得。關頁後僅處理已擷取的快照，避免讀取已釋放的控制器。鎖定時釋放解密預覽。

### 需要保留的回歸邊界

- 還原一般草稿與直接還原聊天／salvage 草稿須各走正確入口，取消還原不留下 pending。
- 游標中間插入任務、刪除最後任務及區塊排序不能丟失後續文字或多生空白段落。
- 預覽勾選須走正式儲存與索引更新；編輯中的文字輸入只保存草稿。
- 已有圖片與 pending 圖片一起排序後，重新開頁、正式儲存與附件預覽仍使用相同順序。
- 背景、鎖定及關頁發生在寫入期間時，保留加密內容，清除解密預覽，阻止過期操作回寫。

流程測試位於 [`test/application/editor/`](../../../test/application/editor/)，UI 整合位於 [`test/presentation/editor/`](../../../test/presentation/editor/)；案例依[測試手則](../../../test/test-handbook.md)放在適當層，不必在每層重複同一規則。

## 刪除日記

刪除日記同時刪除正式附件及相鄰聊天 JSON／恢復檔。日記改日期時一起搬移聊天，來源只在正式提交成功後清除。維護流程見[日記庫檢查與修復](日記庫檢查與修復.md)。
