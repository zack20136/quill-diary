# 人物與姓名查詢

人物名冊的正式資料位於 `vault/people.json.enc`，包含姓名、別名、關係、生日、備註等使用者輸入資料。完整備份會包含這份加密名冊；日記 Markdown、front matter、可攜式匯入匯出格式及備份中的個別日記檔都不保存人物 ID。編輯器的 `@` 功能插入該人物指定的日記名稱（預設為姓名；可在人物編輯表單改選某個別名），仍是一般文字。

## 查詢流程

人物頁、人物詳情或總覽需要統計時，系統才會使用搜尋索引中的標題與 Markdown 可見文字判斷姓名或別名是否出現。同一人物在同一篇日記出現多次仍只計為一篇。

SQLite 的 `people_analysis_documents` 與 `entry_people_analytics` 都是加密衍生快取，不進入備份。前者保存已分析日記的內容 hash，後者保存查詢命中結果。人物姓名集合改變時會重新分析全部索引；只有日記內容改變時則僅分析新增或變更的索引列。人物分析規則目前是初版 generation 1，與人物名冊 catalog 版本互相獨立。

舊索引若尚未保存 `body_visible_text`，只會在第一次開啟人物相關畫面時分批補建。補建過程不讀取人物名冊，也不會退回使用可能包含 fenced code 或連結目的地的搜尋文字；中斷後由仍為空值的索引列接續。

分析採 keyset 分頁，每批最多 256 篇並以單一 SQLite transaction 寫入。寫入交易會再次核對日記仍存在，而且日期與內容 hash 未變，避免分析途中刪除或修改日記留下孤兒結果。少量且短的異動直接處理；超過 8 篇或可見文字合計超過 32 KiB 時，改由同一個暫時 worker isolate 完成所有批次。姓名比對器使用 trie，一次走訪正文即可同時判斷所有正式姓名與別名。

App 啟動時人物分頁不訂閱人物名冊或統計 provider；第一次切到人物分頁後才啟用。人物分頁位於首頁的保留式分頁容器中，首次啟用後即使切到其他首頁分頁，仍保留 provider、搜尋條件、排序與捲動位置，回到人物頁時不會重新建立。人物詳情與總覽只在各自畫面需要時讀取統計；來源沒有變化時不會重掃正文或重寫分析狀態。

切換首頁分頁不等於延長解鎖 session。鎖定或 session 失效時仍會依共用安全流程關閉 SQLite 連線、取消分析並清除已解密人物名冊；人物分頁不自行保存解密資料。SQLite 檔案本身不會刪除，重新解鎖後若 fingerprint、規則版本與內容 hash 均相符，可以直接沿用既有分析結果。

## 名冊格式（catalog v1）

人物名冊使用初版 catalog；`version` 必須為整數 `1`（自訂關係不升版）。

頂層欄位：

| 欄位 | 必填 | 說明 |
|------|------|------|
| `version` | 是 | 僅接受 `1` |
| `updatedAt` | 是 | ISO-8601 時間字串 |
| `people` | 是 | 人物陣列（可為空） |
| `relationshipTypes` | 否 | 缺省時記憶體種子七個內建類型；寫入時一律帶出 |

### 關係類型

每項為 `{ id, labelZh, labelEn }`。

- 內建 id（與舊 enum 名相同，舊資料零轉換）：`family`／`partner`／`friend`／`classmate`／`colleague`／`collaborator`／`other`
- 自訂 id：8 碼小寫 `[a-z0-9]`
- UI 依 app 語系顯示 `labelZh` 或 `labelEn`
- id 唯一；同語系顯示名唯一；人物 `relationships` 必須引用現行類型表中的 id
- 人物頁「管理關係」可新增、依語系改名、刪除、拖曳排序；刪除會清掉人物上的該 id；陣列順序即篩選與編輯 chip 順序

### 人物欄位

- `relationships`：類型 id 字串陣列
- `friendliness`：固定 1–5，對應「陌生／不熟／認識／熟悉／很熟」，必定有值
- 顏色：未自訂時不寫入；依人物 ID 穩定套用預設色盤。使用者選色後才保存不透明 ARGB，清除後回到自動配色
- `mentionName`（可選）：日記 `@` 插入用的別名；必須對應該人物別名之一；省略則用姓名
- 生日只保存月、日
- 顏色、關係類型、`mentionName` 均不參與姓名 fingerprint

格式錯誤、重複人物 ID、重複姓名或別名、未知關係、無效熟悉程度、無效顏色、無效 `mentionName`、生日年份、未知欄位或其他版本均直接拒絕，不執行隱性補值或開發階段格式遷移。

## 錯誤邊界

人物分析失敗只影響統計與相關日記畫面，不得讓日記或人物名冊的正式儲存被回滾或誤報失敗。衍生快取可隨時刪除並由索引重建。
