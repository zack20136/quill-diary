# 備份與還原

完整備份保存加密日記庫供完整還原；可攜式匯出產生可閱讀的 Markdown／HTML。兩者格式與用途不同，`markdown_*.zip` 不能當成完整備份還原。

## 前置條件與權限邊界

條件由 `VaultTransferCapabilities` 決定：

| 操作 | 條件 |
|------|------|
| 本機／外部／Drive 完整備份 | 已解鎖且已有 Recovery Key |
| 可攜式匯入、Markdown／HTML 匯出 | 有效解鎖 session |
| 完整還原 | 已解鎖、尚無 Recovery Key，或狀態為 `recoveryRequired`；一般鎖定須先解鎖 |
| Drive 帳號管理 | 已解鎖，或全新尚未建庫而需要還原；既有鎖定／`recoveryRequired` 不可變更帳號 |

可攜式操作使用 `runSensitiveTask()`。Drive 待處理上傳另外阻擋衝突操作，見下方生命週期。

## 完整備份

### 備份內容與不包含的東西

ZIP 以 `vault/` 為根，不包含最外層目錄名稱。包含與排除的檔案、保護方式與明文成員見[本機儲存](../資料/本機儲存.md)。加密規格見[加密格式](../安全/加密格式.md)。

打包前若已解鎖，會把升級前留在安全儲存的 AI 設定寫進 vault；沒有解鎖 session 則略過。API Key 不寫入 ZIP。

### 建立與交付

`VaultBackupIo.writeBackupZip()` 與 vault 修改共用同一序列。打包前，若 `entries/` 中的 `*.enc.previous` 沒有主檔，先恢復主檔；打包跳過 `.tmp`、`.previous` 與[本機儲存](../資料/本機儲存.md)列出的排除目錄。

所有目的地先建立 `backup_YYYY-MM-DD_HH-MM-SS.zip` 並通過 `inspectBackup()`，再交付：

- 本機：寫入 `backups/`。
- 外部資料夾：由 `deliverToExternalDirectory()` 交付，Android 使用 SAF。
- Drive：先建立 App 私有 staging，再交給原生前景服務。

本機與 Drive 各保留最新 5 份，外部資料夾不自動輪替。本機修復前的 `backup_before_repair_*.zip` 與一般備份共用保留池；命名與數量由 `VaultBackupPolicy` 維護。

### 開發入口與失敗清理

| 階段 | 實作入口與邊界 |
|------|------|
| 前置條件 | [`VaultTransferCapabilities`](../../../lib/application/settings/vault_transfer_capabilities.dart) 統一判斷可備份、匯出、還原及管理帳號的狀態 |
| 本機／外部完整備份 | [`vault_backup_service.dart`](../../../lib/application/transfer/vault_backup_service.dart) 的 inspected pipeline 先建立並檢查 ZIP，失敗不交付 |
| Drive staging | `prepareDriveUploadStaging()` 建立私有 ZIP 與工作狀態，再由 `DriveUploadCoordinator` 交原生服務；交接前失敗由本機清暫存 |
| 實際 ZIP I/O | [`vault_backup_io.dart`](../../../lib/infrastructure/storage/portable/vault_backup_io.dart) 與 vault 修改共用序列，避免一半新、一半舊的日記庫內容 |
| 還原協調 | [`RestoreBackupFlow`](../../../lib/application/restore/restore_backup_flow.dart) 執行預檢、必要驗證與 session 收尾；UI 不直接覆蓋 vault |

Drive 交接後的暫存與遠端殘檔由 persisted job 生命週期管理，不能在 Dart 頁面離開時直接刪除服務仍在使用的 ZIP。下載或外部選檔的 temp file 在共用流程結束後清除；還原失敗與使用者取消不能清空原 vault。完整上傳結果必須經遠端驗證，不能只依進度到 100% 判定成功。

### 完整備份檢查

`inspectBackup()` 驗證 ZIP 可讀、entry 路徑安全、不是 Markdown 匯出，且包含可解析的 `recovery.json`，以及 manifest 或至少一份加密日記。結構檢查不代表每份內容都已解密驗證。

金鑰驗證優先取 manifest，沒有時取可用日記樣本。金鑰必須對應建立該份備份時的 recovery metadata。

### 換手機或重裝

1. 在舊手機將需保留的草稿正式儲存，保存備份當時的復原金鑰。
2. 建立最新外部 ZIP 或 Drive 備份並等待成功。
3. 新手機由「匯入外部備份」或同一 Google 帳號的 Drive 還原，不能改用「匯入日記」。
4. 需要驗證時輸入舊備份的金鑰，確認日記、附件、人物、標籤與釘選恢復後才清除舊手機。

草稿、API Key 與個人化偏好不隨備份搬移。服務、網址與提示詞在加密日記庫內，會隨完整備份走。Drive 是手動備份，不即時同步兩台手機。

### 外部選檔與 materialize

外部備份與可攜式文件先經系統選檔，再材料化為本機可讀檔。依賴版本見 [`pubspec.yaml`](../../../pubspec.yaml)，實作見 [`picked_file_materializer.dart`](../../../lib/infrastructure/storage/shared/picked_file_materializer.dart)。

Android 使用 `AndroidPlatformFile`／`safHandle`，完成後呼叫 `releaseGrant()`；`allowBytesFallback` 預設為 false，避免整檔載入記憶體。寫入外部資料夾使用自製 SAF channel。變更 `file_picker` 版本須確認這些 API 及 grant 釋放仍成立，並做實機選檔／還原驗證。

## 還原

本機、外部與 Drive 下載的備份共用 `RestoreBackupFlow`：預檢 → 必要時驗證備份金鑰 → 換入 vault → `finishRestoreSession()`。

`RestorePrecheck` 比對 vault ID、KDF 世代及目前 trusted session，決定能否沿用 session、需要備份金鑰或重新啟動。

| 預檢欄位 | 用途 |
|------|------|
| `sameVaultId` | 是否為同一日記庫，不能只因檔名相似就沿用 session |
| `sameRecoveryGeneration`、`recoveryKeyRotatedSinceBackup` | 是否同一復原金鑰世代；舊備份仍需舊金鑰 |
| `expectsTrustedUnlockAfterRestore` | 預期可由目前可信裝置接手 |
| `expectsRecoveryKeyAfterRestore` | 需準備備份當時的復原金鑰 |
| `canResumeTrustedSession(priorSession)` | 真正換入後是否可沿用原可信 session，否則回到安全分流 |

預檢只讀取備份與裝置條件；真正換入前才依流程驗證金鑰並執行還原。`inspectBackup()` 結構正確、復原金鑰可解密樣本、全部日記可讀，是不同層次的驗證，不能合併成一個成功旗標。

### 目錄替換與清理

1. 解壓到 `vault_restore_tmp`，確認至少有 recovery metadata 與 `entries/`。
2. 複製成 `vault.incoming`，舊 vault 改名為 `.bak_<時間戳>`。
3. incoming 改為正式 vault，成功後刪除舊目錄；替換失敗嘗試回滾。
4. 關閉舊資源、刪除索引、清除一般草稿與解密預覽，清除 metadata 快取，必要時清除 trusted access。

未完成聊天與遠端清理紀錄不在 ZIP；整個 vault 換入後不保留。還原不改寫 vault 外的個人化偏好，也不改寫安全儲存裡的 API Key。加密 AI 設定在 vault 內，會隨還原換入。

### 還原後 session

| 條件 | 行為 |
|------|------|
| 已提供備份金鑰 | `unlockWithRecovery()`，由該路徑重建索引 |
| `canResumeTrustedSession(priorSession)` | `resumeSessionAfterRestore()`，確認索引可用並重建 |
| 預期 trusted unlock，但無法沿用 | 進入 `recoveryRequired` |
| 其餘情況 | `bootstrapAfterRestore()`；必要時由還原收尾重建索引 |

收尾重設啟動狀態、清除路由快照並刷新首頁、人物與索引 Provider。完整 session 規則見[解鎖與會話](../安全/解鎖與會話.md#還原後的-session-分流)。

## 可攜式匯出

Markdown／HTML 只匯出正式日記，不包含聊天 JSON、人物名冊或原資料 ID。產物是明文，匯出前顯示篇數、附件、日期範圍與估算大小，並讓使用者選篇確認。

| 格式 | 產物與附件規則 |
|------|------|
| Markdown | `markdown_*.zip`，以 `日期/標題或備援名稱/index.md` 及附件散檔保存；無排除附件選項 |
| HTML | `html_*.html` 單一檔，可由首頁、總覽範圍或人物相關日記匯出；預設內嵌圖片與附件清單，可關閉 |

HTML 日期含星期與時分；圖片名稱使用 `image-1.<ext>` 等通用序號，不使用原檔名。選取原圖合計達 50 MB 時顯示大檔提示。

兩種格式皆可選擇隱藏人物名稱（預設關），只替換名冊可辨識的姓名／別名，不能視為完整匿名化；日期、地點、未登錄姓名及照片仍可能辨識人物。App 只交付檔案，不自動傳給外部工具。

可攜式往返一律建立新日記與附件，不提供共同編輯、同步或自動去重。Markdown 可保留內文、標籤及附件；HTML 可還原內文、標籤、任務與 data URI 圖片，非圖片附件只有清單，無法恢復原檔。隱藏後再匯入的正文仍是代號。

## 可攜式匯入

設定頁先選 `.zip`、`.md`、`.html` 或 `.htm`；未選檔時可改選資料夾。先解析候補，不立即寫入；預覽可選篇，取消清除暫存，至少選一篇才可確認。

- 預覽列出可匯入篇數、解析失敗檔案、略過附件及可能重複篇數。
- 重複候補依日期與標題比對，空標題改用正文前綴；仍一律新增，不自動合併。
- ZIP 優先辨識 Easy Diary 完整備份，否則使用 Markdown／HTML 匯入；無內容回傳 `zipNoEntries`。
- 資料夾遞迴尋找支援格式。Markdown 解析 front matter 與附件，HTML 解析 article、日期、標題、標籤、內文及圖片。
- 本地附件只接受匯入根目錄內的安全相對路徑；data URI 圖片轉為 pending bytes。
- Easy Diary 圖片先嗅探 MIME 並解碼驗證，不可解碼者略過並計入 `skippedAttachments`。
- 確認後逐篇走 `VaultRepository.saveEntry()`；至少成功一篇時同步標籤樣式。

## Google Drive 交付流程

Google Drive 備份與還原使用相同的完整備份 ZIP，只是交付位置不同：

- 上傳時：App 先建立並檢查 `backup_*.zip`，再交給 Android `dataSync` 前景服務以 resumable upload 上傳到 `appDataFolder`
- 還原時：先下載到 temp file，再走一般 `restoreFromBackupFile(...)`

### 背景上傳生命週期

- 僅 Android；由使用者手動啟動，不是自動排程同步
- 設定頁入口：[`settings_page.dart`](../../../lib/presentation/settings/pages/settings_page.dart) → [`DriveUploadCoordinator`](../../../lib/application/settings/drive_upload_coordinator.dart)（ZIP 準備後交原生 FGS，非 Dart 前景同步上傳）
- 建立 ZIP 後，到原生前景服務完成啟動與交接前，請保持 App 顯示在畫面上；否則 Android 12+ 可能拒絕啟動前景服務
- 交接後通知列會顯示進度與停止動作。可切換 App、鎖定螢幕或從最近工作移除 Activity；請勿強制停止 App
- 通知、授權與上傳錯誤會跟隨 App 語言；未同步或無效語言時回退繁體中文
- 任何仍存在的 persisted job（含 `STATUS_PENDING`／`PRUNE_PENDING`／`CANCEL_CLEANUP_PENDING`）經 `uploadBusy`（`blocksConflictingDriveActions`）會擋住新上傳、還原與一般帳號操作；取消清理需重連原帳號時除外
- **同一個 FGS 存活期間**：短暫離線會進入 `WAITING_FOR_NETWORK`，恢復後依 `retryCount` 與 `nextRetryAt` 自動重試
- **遠端完成驗證後程序終止**：保留 `STATUS_PENDING` 或 `PRUNE_PENDING`。背景事件只更新 persisted job，不啟動 Dart Google 收尾；下次啟動、回到前景或進入設定時才完成成功紀錄與 finalize，不會重新上傳
- 每個 8 MiB chunk 經 Google 確認後立即以 progress durability 持久化；通知與設定頁都以同一份 `confirmedOffset / sizeBytes` 無條件捨去顯示整數百分比
- 不提供遠端完成驗證前的跨程序續傳。授權失效、重試耗盡或 FGS 啟動被拒等實際上傳失敗，仍會寫入 failure notice；使用者需重新建立備份

#### 取消與異常中止（`CANCEL_CLEANUP_PENDING`）

下列情況都會先寫入 `CANCEL_CLEANUP_PENDING` 並中止傳輸，**不**建立 failure notice：

- 使用者主動停止
- dataSync 額度逾時（`onTimeout`）
- 服務銷毀（`onDestroy`）
- crash／強制停止後的冷啟動 leftover

接著以 `DriveRemoteFileCleanup.completeCancelCleanup()` 查詢遠端：

- 已驗證完成 → 升 `STATUS_PENDING`／`PRUNE_PENDING`，走原本成功收尾
- 已驗證完成且另有未驗證殘檔 → 必須刪殘檔成功後才升 `STATUS_PENDING`；刪除失敗則 `RetryLater`
- 尚未通過驗證 → 刪除殘檔後清本機 job；刪除失敗則 `RetryLater`
- 查詢暫時失敗（`RetryLater`）→ 保留 pending；UI 顯示「正在清除未完成的 Google Drive 備份…」，下次再試
- 授權失效／需重新登入（`NeedsReauth`，`lastErrorCode=cleanup_needs_reauth`）→ 保留 pending；允許重新連結原帳號（`job.accountEmail`）後再對帳
- 目前帳號與 job 不符（`AccountMismatch`，`lastErrorCode=cleanup_account_mismatch`）→ 保留 pending；提示連回原帳號，或確認後放棄清理

對帳完成前不能開始新的上傳；一般也會鎖住切換／中斷帳號。授權錯誤時例外允許重連原帳號；使用者也可確認後呼叫 `abandonCancelCleanup`：有相符 token 時盡力刪已知殘檔，再一律清本機 job 解鎖（殘檔刪除失敗不阻擋）。放棄後不會寫入成功備份紀錄。

對帳觸發時機：

1. 使用者停止且 worker 已退出
2. 系統逾時／服務銷毀時，若 worker 已不在，立刻排程對帳
3. worker `finally`
4. 下次啟動、回前景或進入設定時的 `getState`

worker 是否已退出以 `uploadWorkerAlive` 為準（`Future.cancel` 後 `isDone` 不代表執行緒已結束；`startUpload`／重試／網路恢復也看此旗標）：

- 使用者停止後最多等待約 15 秒；逾時仍未退出則保留 pending，由 `finally` 或下次 `getState` 再對帳
- 服務銷毀時若短等待後執行緒仍未退出，保留 `uploadWorkerAlive` 並只推 pending，避免對尚在跑的 HTTP 誤刪；行程結束後 companion 旗標會重置

### 成功收尾

持久狀態只保留：

```text
STAGED → UPLOADING ⇄ WAITING_FOR_NETWORK → STATUS_PENDING → PRUNE_PENDING
                                    ↘ CANCEL_CLEANUP_PENDING →（刪 job 或升 STATUS_PENDING）
```

- `STATUS_PENDING`：遠端已驗證的待辦；App 以 `jobId` 冪等寫入本機成功紀錄（並清除 `lastFailure`）。啟動、回前景或進入設定以 `getState` 做掉（不依賴已解鎖 vault；自動收尾僅非互動 Google 授權）
- `PRUNE_PENDING`：亦會冪等寫成功紀錄（防冷啟動 store／native 脫節）；僅在 App 前景執行靜默 prune，最多等待 10 秒，不論成功、失敗或逾時都 finalize，再以 `getState` 對帳清 UI（不可本地幽靈清空）。上傳前補清與成功收尾共用同一個 single-flight 靜默 prune；兩者都最多等待 10 秒，底層呼叫完成前不重複啟動
- `CANCEL_CLEANUP_PENDING`：取消或異常中止後，等待確認遠端檔再刪本機 job，或升為 `STATUS_PENDING`；對帳完成前會擋住新的上傳。授權失效時可重連原帳號或確認放棄清理。
- Flutter `EventChannel` 只喚醒再 `getState`；`markStatusRecorded` 成功回 job map、失敗回 `null`；`prune`／`delete` 的 `interactive` 必須一致
- 遠端完成驗證要求 `remoteFileId`、檔案大小、`uploadJobId` 與 Drive `md5Checksum` 全部符合；本機 MD5 只在 staging 建立後計算一次

OAuth、帳號切換、scope 與權限頁細節請看 [../google/Google-Drive-OAuth-設定.md](../google/Google-Drive-OAuth-設定.md)。

## 主要實作與驗證

完整備份／還原 I/O 在 [`vault_backup_io.dart`](../../../lib/infrastructure/storage/portable/vault_backup_io.dart)，可攜式 I/O 在 [`portable/`](../../../lib/infrastructure/storage/portable/)，上層由 [`RestoreBackupFlow`](../../../lib/application/restore/restore_backup_flow.dart) 與各 transfer capability service 協調。

回歸驗證應涵蓋完整備份往返、包含／排除資料、不安全路徑、還原失敗保留原 vault、不同金鑰世代、可攜式選篇與明文邊界，以及原生 Drive 取消對帳和成功收尾。測試分層見[測試手則](../../../test/test-handbook.md)。

實機驗收另確認系統檔案供應商的 URI 權限、外部目錄交付、Play 安裝版 Google 授權與通知停止；這些平台行為不能只由 Dart mock 驗證。換機案例須包含完成聊天的分支與正式圖片、人物名冊、標籤、釘選，以及未完成草稿確實排除；保留舊裝置到新裝置驗證完成。
